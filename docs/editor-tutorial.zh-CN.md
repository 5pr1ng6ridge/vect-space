## 1. 编辑器是什么

VECTSPACE 剧情编辑器是一个**独立的 Tauri 2 桌面应用**，用有向节点图的方式编辑游戏的 YAML 剧情。它不是另一套私有工程格式：所有编辑最终都写回仓库里的

- `game/manifest.yaml`（项目清单：场景、素材、变量、角色、动作、按钮、UI 动效、章节地图的登记）
- `game/scenes/*.yaml`（每个场景的节点图）
- `game/animations/*.yaml`、`game/actions/*.yaml`、`game/ui/buttons/*.yaml`、`game/ui/motions/*.yaml`、`game/chapter-map.yaml`（各类子文档）

编辑器与游戏共享同一套 Rust 内容模型和校验器：**保存前**会在内存里验证完整候选项目，通过后才写入磁盘；游戏运行时读到的 YAML 一定与编辑器认可的格式一致。

### 能做的事情

| 能力               | 说明                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------- |
| 剧情图             | 节点 + 端口连线，拖线即改 YAML 的跳转字段；自动布局、小地图、吸附                             |
| 脚本视图           | 按链段批量阅读/编辑对话，支持多选、批量改角色、多行批量粘贴                                   |
| 节点类型           | 覆盖运行时全部节点类型（叙事 / 逻辑 / 画面 / 交互 / 声音 / 流程 / 窗口）                      |
| 长文本             | 全屏排版工作区，真实 KaTeX 与分页预览                                                         |
| 关键帧时间线       | 立绘 / 镜头 / 视频 / BGM / 四槽环境声 / 按钮轨道 + 关键帧、缓动、事件，并用真实运行时构造预览 |
| 画面实时预览       | 背景转场 / 幕布 / 屏幕效果共享 `SceneSurface` 预览：静音、可取消、确定性定位                  |
| 章节地图           | 房间、章节热点、装饰物的拖放布置，20px 网格                                                   |
| UI 动效 / 按钮模板 | 独立全屏工作区，做对话框动效和可点击按钮                                                      |
| 素材               | 导入检查、引用关系、循环帧动画创建                                                            |
| 项目数据           | 变量（save/profile）、角色与表情、立绘动作库、内容版本                                        |
| 诊断               | 实时校验 + 完整校验，问题按场景分组、可点击定位                                               |
| 安全               | 撤销/重做、事务化多文件保存、备份、外部改动指纹保护                                           |

### 编辑器不提供的功能

- 不提供美术、音频、视频的制作或转码；素材必须是已符合格式的文件。
- 时间线**没有字幕/对话轨**（字幕由 `say` 节点和对话框负责）。

## 2. 安装与启动

### 2.1 环境要求

| 工具                            | 版本 / 说明                                        |
| ------------------------------- | -------------------------------------------------- |
| Node.js                         | `24.19.0`，由 Volta 管理                           |
| Rust                            | stable MSVC 工具链（`rustup default stable-msvc`） |
| Git LFS                         | 二进制游戏素材使用 LFS                             |
| Microsoft Edge WebView2 Runtime | Windows 上的 Tauri 运行环境                        |

PowerShell 一键安装（装完重启终端）：

```powershell
winget install --id Volta.Volta --exact
winget install --id Rustlang.Rustup --exact
winget install --id GitHub.GitLFS --exact
winget install --id Microsoft.EdgeWebView2Runtime --exact
volta install node@24.19.0
rustup default stable-msvc
git lfs install
```

### 2.2 首次安装依赖

在仓库根目录：

```powershell
git lfs pull        # 先把素材占位文本换成真实文件
npm ci              # 安装全部依赖（npm workspace，包含编辑器与共享包）
```

### 2.3 启动编辑器

在仓库根目录：

```powershell
npm run editor:dev
```

也可以进入 `editor/` 目录运行：

```powershell
cd editor
npm run tauri dev
```

启动前会自动执行素材预检。如果 clone 里是 LFS 指针文本而不是真实图片/字体/音频/视频，启动会**直接停下**并列出受影响的路径和恢复命令，而不是打开一个残缺的预览。

如果当前终端找不到 Cargo：

```powershell
$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"
```

### 2.4 打包安装版

```powershell
npm run editor:build
```

NSIS 安装包输出在：

```text
target/release/bundle/nsis/
```

## 3. 五分钟上手

1. 启动编辑器，在欢迎页点「打开项目目录」，选择**仓库根目录**，或直接选择包含 `manifest.yaml` 的 `game/` 目录。
2. 左侧面板默认显示「场景」，点选 `prologue`（演示场景）。
3. 中间工作区默认是「剧情图」。左键点任意 `say` 节点选中它。
4. 右侧检查器把「对话文本」改一句话，点输入框外或按 `Ctrl+Enter` 提交；顶栏会显示「未保存」。
5. 想改流程：从节点右侧的输出端口按住拖线到另一个节点，松手即写入跳转字段。
6. 按 `Ctrl+S` 或顶栏「保存项目」。保存前编辑器会校验整个项目，问题会集中显示在「问题」面板里。
7. 想马上看效果，运行游戏本体：根目录 `npm run tauri dev`。

> 记住三件事：**改完要保存**、**保存前看问题面板**、**节点位置不会写进剧情文件**（位置存在 `game/.vectspace/layout-v1.json`）。

## 4. 界面总览

主界面由五块构成：

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 顶栏：项目名 ▾ / 场景 ▾ │   搜索台词、节点、场景与素材… (Ctrl+F)   │ 面板开关 · 章节地图 · 游戏预览 · 撤销 · 重做 · 保存项目 │
├──┬──────────────┬──────────────────────────────────────┬────────────────┤
│活│ 左侧面板       │ 工作区：剧情图 / 脚本                    │ 右侧检查器        │
│动│ （随活动栏切换）│ 画布左上角：添加节点 ▾ · 自动布局 · 适合画布 │ （所选节点的属性） │
│栏│              │                                      │                │
├──┴──────────────┴──────────────────────────────────────┴────────────────┤
│ 状态栏：所选节点 · N 个节点 · 错误/警告数（点击打开「问题」）                    │
└──────────────────────────────────────────────────────────────────────────┘
```

### 4.1 欢迎页

- 「打开项目目录」：弹出系统目录选择框。
- 「最近打开」：列出最近打开过的项目（最多 6 个，记录在本机，换机器不会同步）。
- 打开项目时会显示进度；打开失败的原因直接显示在卡片里。

### 4.2 顶栏

| 位置 / 按钮                | 作用                                                              |
| -------------------------- | ----------------------------------------------------------------- |
| 项目名 ▾                   | 项目菜单：打开其他项目、项目设置、完整校验项目                    |
| 场景 ▾                     | 切换当前场景（入口场景带「（入口）」标记）                        |
| 搜索框                     | 全项目搜索台词、角色名、选项文字、节点 ID、场景与素材（`Ctrl+F`） |
| 左 / 右面板开关            | 分别收起或展开左侧面板和右侧检查器，扩大画布                      |
| 章节地图                   | 进入章节地图工作区（首次会自动创建空地图）                        |
| 游戏预览                   | 用真实运行时预览当前场景或所选节点                                |
| 撤销 / 重做                | 等同于 `Ctrl+Z` / `Ctrl+Y`；按钮悬停时显示快捷键                  |
| 已保存 / 未保存 · 保存项目 | 保存状态与保存按钮（`Ctrl+S`）                                    |

**项目搜索**：输入即搜索，按字段匹配（不会因为字段名误匹配所有节点）。`↑` / `↓` 选择结果，`Enter` 打开，`Esc` 清空。节点结果会跳到对应场景并选中节点，素材结果会打开素材库。

### 4.3 活动栏与左侧面板

窗口最左侧的一列图标切换左侧面板；再次点击当前图标会收起面板。

| 图标     | 面板内容                                                                                       |
| -------- | ---------------------------------------------------------------------------------------------- |
| 场景     | 场景列表与筛选；每行显示节点数、「项目入口」与问题数；悬停显示重命名 / 删除按钮                |
| 素材     | 素材库：虚拟文件夹、类型筛选、导入、帧动画、素材详情                                           |
| 角色     | 角色显示名、姓名 / 正文颜色、默认表情与缩放、表情图                                            |
| 变量     | 剧情变量：作用域（随存档 / 全局）、类型（开关 / 整数 / 小数 / 文本）与默认值                   |
| 资源库   | UI 动效、按钮模板、立绘动作。每行一个条目：铅笔按钮打开编辑器，「⋯」菜单里是副本、重命名、移除 |
| 问题     | 校验问题，按场景分组、错误在前；点击跳转到对应节点（详见第 14 章）                             |
| 项目设置 | 位于活动栏底部：内容版本、默认语言、项目入口场景和项目统计                                     |

「问题」图标在有问题时显示数量（有错误时为红色）。

### 4.4 工作区两种视图

工作区顶部切换「剧情图 / 脚本」，右侧显示当前视图的常用操作提示。

### 4.5 右侧节点检查器

未选中节点时显示提示。选中后顶部显示：

- 节点类型图标与名称；
- 节点 ID——点击即可就地重命名（重命名前会说明对引用与存档的影响）；
- 「入口」标记（场景入口节点）；
- 「⋯」节点操作菜单：设为场景入口、重命名 ID、创建副本、转为 / 展开为关键帧时间线、更改类型、删除节点。

下面是该节点类型的专属表单，详细字段见第 7 章。「下一节点」等目标下拉会显示目标节点的类型与内容摘要，旁边的定位按钮可在剧情图中选中目标节点。

### 4.6 状态栏

- 所选节点（类型 · ID）；
- 当前场景的节点数；
- 右侧：`检查通过`，或「N 个错误 / N 个警告」，点击打开左侧「问题」面板。

### 4.7 面板宽度

拖动左右面板边界（或聚焦边界后用方向键，`Shift` 加大步长）可调整宽度：

- 左侧面板：220–480px，默认 280px
- 右侧检查器：300–560px，默认 340px

**拖到底直接收起**：把边界继续往里拖，越过最小宽度约 56px，面板就会收起；不松手再往外拖，面板会在同一次拖动里重新展开。
键盘同样可以：面板已是最小宽度时再按一次朝内的方向键（左侧栏是 `←`，右侧栏是 `→`）就会收起，按住不放不会一路收起。

**收起后边缘留一条 12px 的拉手**：它停在窗口边缘，可以从这里把面板拖出来（先以最小宽度出现，再跟着鼠标走），也可以**单击展开**，
面板回到收起前记住的宽度；用键盘时聚焦这条拉手，按朝外的方向键（左侧栏 `→`、右侧栏 `←`）、`Enter` 或空格同样展开。
收起不会改写记住的宽度。

面板宽度只保存在本机，不会写入项目，也不会让项目变成「未保存」。

### 4.8 通用交互约定

| 场景                | 约定                                                                                                                                                  |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 输入框              | 失去焦点或按 `Enter` 时提交（多行文本为 `Ctrl+Enter`），`Esc` 还原；一次编辑只产生一条撤销记录                                                        |
| `Ctrl+S`            | 无论焦点在哪里，都会先提交正在编辑的字段再保存                                                                                                        |
| `Ctrl+Z` / `Ctrl+Y` | 焦点在文本框里时撤销 / 重做文字本身；否则撤销 / 重做项目修改                                                                                          |
| `Esc`               | 先关闭弹出菜单、取消正在进行的拖拽、让输入框失焦；都没有时才退出全屏工作区。输入中和输入法组字时不会退出                                              |
| 删除与移除          | 可以撤销的删除会直接执行，并弹出带「撤销」按钮的通知；会影响玩家存档的操作（重命名场景 / 节点、更换节点类型、放弃未保存更改）会先弹出说明后果的确认框 |
| 通知                | 成功提示几秒后自动消失；错误和保存警告会一直保留，直到手动关闭                                                                                        |
| 新建 ID             | 输入时实时校验并直接说明原因（格式、重名、文件路径冲突）                                                                                              |

## 5. 剧情图编辑器

### 5.1 节点卡片读法

每张卡片显示：

- 顶部：类别图标（按叙事 / 逻辑 / 画面 / 声音 / 交互 / 流程着色）、类型名、节点 ID；
- 右上角标记：旗帜 = 场景入口，沙漏 = 等待演出完成后再继续，红色数字 = 该节点的问题数（悬停可看说明）；
- 正文：对话显示说话人的**显示名**和台词；其他节点显示一行中文摘要（例如「落下幕布 · 交叉淡化」「如果 affection 大于等于 3」）；
- 输出：普通节点只在右侧边缘有一个连接点；`choice`、`condition`、`jump` 这类有多个出口的节点会逐行列出出口名称（悬停可看连接目标）。

### 5.2 拖线改跳转

从输出连接点拖到目标节点左侧的输入点，松手即改写对应跳转字段。跨场景跳转由 `jump` 节点的「目标场景」决定；图中只画同一场景内的连线，分支连线会标注出口名称。

### 5.3 添加与插入节点

1. **画布工具条「添加节点 ▾」**：按类别分组的节点菜单，新节点出现在当前视口中央并自动选中。
2. **右键画布空白处 →「在此处添加节点」**：新节点放在右键的位置。
3. **节点两侧的 ＋**：悬停节点时出现，分别在前面 / 后面插入节点，并自动接管原有连线。
4. **右键节点 →「在前面插入 / 在后面插入」**：同上。

插入失败时会给出原因（例如源节点已变化），不会半途写入。

### 5.4 右键菜单、复制与副本

右键节点的菜单：从此处预览（`Ctrl+Enter`）、打开时间线 / 长文本工作区、设为场景入口、在前面 / 后面插入、复制（`Ctrl+C`）、创建副本、删除（`Delete`）。右键画布空白处：在此处添加节点、粘贴、自动布局、适合画布。

- `Ctrl+C`：复制选中节点到编辑器内部剪贴板。
- `Ctrl+V`：粘贴到鼠标指针位置（输入框内不会触发）。
- 「创建副本」：原地复制，ID 自动加 `_copy` 后缀。

粘贴会做防呆处理（重新分配冲突 ID、保留来源角色信息）。

### 5.5 删除节点

- 选中节点后按 `Delete`，或使用右键菜单 / 检查器「⋯」菜单里的「删除」；`Backspace` 不会删除剧情图节点。
- 焦点在输入框、下拉框、输入法合成中、按住不放的重复按键，以及菜单或对话框打开时，`Delete` 不会删除节点。
- 只有一个后继：直接删除，原本指向它的连线（以及场景入口）改接到这个后继，并弹出带「撤销」按钮的通知。
- 有多个后继：弹出对话框，选择由哪个节点接管原有连线。
- 没有任何后继：从同场景其它节点里挑一个节点接管。
- 批量删除：脚本视图多选后按 `Delete`，所选节点必须是同一条连续链（跨越分支或合流会被拒绝并说明原因）。
- 场景至少要留一个节点；`long_text` 开始节点如果还被接续 / 控制节点引用，也会被拦下。
- 若画布选择里包含布局组（组框），`Delete` 会被画布吃掉、不做任何删除；只有选中**恰好一个**节点时才会走上面的删除流程（不会误删检查器里残留的旧节点）。
- 删除会同步清理编辑器布局和该节点的时间线预览设置。

### 5.6 视图与布局

- 画布吸附到 **16px** 网格；缩放范围 0.15–1.8。
- 左下角是缩放控件，右下角是可拖拽 / 缩放的小地图（入口节点为强调色）。
- 画布左上角工具条：「添加节点 ▾」「自动布局」（ELK 分层布局，向右排布）「适合画布」。
- **布局组**：`Ctrl/⌘`（或 `Shift`）点击可选节点卡片或组框，实现节点+节点、组+节点、组+组加选。
  - 右键「将所选项组成父组」或 `Ctrl+L`：把当前选择（祖先与后代先做去重规范化）包成一个新的父组；只选中一个组时右键「解散此组」或按 `Ctrl+L` 解散该层，子节点 / 子组仍保留。若浏览器/WebView 占用 `Ctrl+L`，改按 `Ctrl+Shift+L` 或使用右键菜单。
  - 组框只在与边框 / 标题栏交互时可点，卡片、端口和插入按钮不受遮挡；拖动标题栏会带着全部后代节点整块吸附移动，只提交一次撤销记录。
  - 自动布局只把**根组**当作一个刚体单位（内部所有嵌套偏移保持不变），组内节点不会被拆开。
  - 组是可嵌套的，少于两个直接子项（空组或只剩一个）的层会自动折叠并把幸存子项提升，不会丢弃后代。
- 节点位置、画布视口和嵌套布局组保存在 `game/.vectspace/layout-v1.json`，**不写进剧情文件**。每个组都带稳定 id。

### 5.7 双击与预览

- 双击 `timeline` 节点进入关键帧时间线工作区；双击 `long_text` 节点进入长文本工作区。
- 双击其他节点会展开右侧检查器，并把焦点放到第一个字段上，直接开始编辑。
- 想从某个节点开始看效果：选中节点后按 `Ctrl+Enter`，或右键节点 →「从此处预览」。预览使用游戏同一套运行时与表现组件，可以按空格 / `Enter` 推进、补全打字、选择分支，也可以点「重置并从此节点开始」跳过前置节点。预览舞台内会显示鼠标的 1920×1080 设计坐标。
- 预览是**单窗口**的：计时器、窗口标题和阻挡会在本窗口内真正运行（状态栏会显示窗口标题与活动的计时器，被阻挡时会显示提示，且不会发出被拒绝的翻页请求）；而对**另一个窗口**的请求（改标题、阻挡、推进）和「打开副窗口」不会生效；窗口位置/大小与窗口层级对两个窗口都不会生效（预览绝不会移动、缩放或置顶编辑器自己的窗口）。预览会在画面上方明确提示，需要在桌面双窗口运行游戏来验证。
- 顶栏「游戏预览」进入同一预览，保留「从场景入口开始 / 从所选节点开始 / 重置并从此节点开始」三个起点按钮；点工具栏左侧「返回编辑器」回到剧情图。

### 5.8 场景管理

- 添加场景：场景面板右上角的 ＋，输入新场景 ID（只允许字母、数字、`.`、`_`、`-`，1–128 字符；输入时会实时提示问题）。
- 重命名场景会更改文件路径并影响既有存档，确认框会说明影响；已存在的 ID 会被拒绝。
- 删除场景只把它从项目中移除，原场景文件保留在磁盘上；删除后可在通知里点「撤销」恢复。
- 项目入口场景在「项目设置」里更换；入口场景不能删除。
- **场景用途**：每个场景只属于一个窗口。场景面板里的「添加副窗口场景」按钮会新建副窗口专用场景，
  已有场景可用行内的「设为副窗口专用 / 设为主窗口专用」切换（副窗口专用的场景会标出
  「副窗口专用」）。详见 7.4 的「窗口与场景用途」。

## 6. 脚本视图

脚本视图适合**连续写作和批量修改**，把当前场景按「链段」切成一条条可读列表。

- **版式**：按剧本排版——对话行左侧是说话人的显示名（旁白留空），右侧是台词；非对话节点显示为一行中文摘要（例如「落下幕布 · 交叉淡化」），并带类型图标。接续上一段的对话会标出「接续上一段」。
- **链段起点**：工具栏「链段」下拉选择从哪个节点开始阅读；一段是一条连续链，遇到分支、跳转、合流或已访问节点就停。
- **筛选**：工具栏右侧「筛选本链段…」按节点 ID 或正文过滤。
- **多选**：`Ctrl/⌘ + 点击` 加选，`Shift + 点击` 范围选择；工具栏显示「N 项已选」。
- **批量改角色**：多选后出现「批量改角色…」下拉（含「旁白」），一次改掉所选对话的说话人。
- **行内编辑**：每行都可以直接改角色和正文。显示模式（新对话段 / 接续对话段）、揭示动画（默认揭示、打字机、逐行扫入、下落淡入）和打字速度属于高级设置，**只在当前选中的行上显示**，避免满屏下拉框干扰阅读。
- **键盘**：
  - `Enter`：以当前行说话人插入下一句对话；
  - `Shift+Enter`：正文内换行；
  - `Ctrl/⌘+A`：全选当前链段；
  - `Ctrl/⌘+C`：把所选对话复制为「角色 + Tab + 正文」多行文本；
  - `Delete` / `Backspace`：删除所选节点（多选时走批量删除规则）；焦点
    在输入框或可编辑区域、输入法合成中、按住不放的重复按键、行内按钮
    （含行摘要与插入菜单）以及打开的对话框（含批量粘贴预览）都不会触发；
  - 从剧情图切到脚本视图时，图中选中的节点会被沿用为脚本视图的当前选择
    （同时作为链段起点），可以直接继续删除或编辑。
- **批量粘贴**：在脚本视图里粘贴「角色⇥正文」的多行文本会先弹出「批量粘贴预览」，确认后按顺序插入为 `say` 节点；正文为空的行会被标错。
- **＋（插入出口）**：在当前节点后插入新对话；若节点有多个出口，先让你选择插到哪个出口。
- **跳转导航**：`jump` 行的目标可以直接点击跳过去，跨场景会切换场景。
- 点摘要区域可「在图谱中打开」对应节点。

**`set` 设置变量**

| 字段     | 说明                                                                                  |
| -------- | ------------------------------------------------------------------------------------- |
| 目标变量 | 显示 `id · 类型`；未声明时显示「— 未声明 —」                                          |
| 操作     | assign·赋值 / add·加 / sub·减 / mul·乘 / mod·取模 / append·追加文本 / toggle·布尔翻转 |
| 操作数   | 字面量或变量；按变量类型使用不同的编辑器                                              |

操作与类型是联动的：boolean 只能用 toggle；string 只能用 append；integer 支持 mod（且除数不能为 0）；number 不支持 mod。

**`condition` 条件分支**

- 运算符：Eq·等于、Ne·不等于、Lt、Le、Gt、Ge、And·全部成立、Or·任一成立、Not·取反。
- 比较项 = 左值 + 右值，各可选变量或字面量；And/Or 可递归添加子条件（至少一个子条件），Not 递归单个条件。
- 数值比较只接受 integer / number；Eq/Ne 两侧类型必须兼容。
- 出口：`成立` 与 `否则`。

**`jump` 跳转**

| 字段     | 说明                                                                            |
| -------- | ------------------------------------------------------------------------------- |
| 目标场景 | 留空表示当前场景；只列出与当前场景用途相同的场景（按真实场景 ID，而不是文件名） |
| 目标节点 | 同场景时用下拉选择；跨场景时填目标节点 ID                                       |

**`open_window` 打开副窗口**

| 字段       | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| 副窗口场景 | 必填；只列出用途为「副窗口」的场景，按场景里写的真实 ID 显示 |
| 下一节点   | 同场景的下一节点；节点不阻塞，主窗口推进到它之后继续执行     |

这个节点把指定场景交给游戏唯一的一个副窗口（真正的原生系统窗口）。重复执行不会
创建第二个窗口，而是在同一个窗口里替换副窗口运行时与场景。

一次更新里出现多个 `open_window` 时由**最后一个**决定副窗口显示哪个场景；新游戏、读档、
回到标题或场景切换只在同一次更新没有自己的窗口请求时，才会关闭原来的副窗口。

- **主窗口**的剧情运行时与章节地图里的**章节重演**都会真正打开/替换副窗口；副窗口
  自身经过该节点时只正常推进，不会开窗。重演内容是临时的，其中的变量与对白不会进入
  正式进度、档案文件、存档或正式对白历史。
- 副窗口拥有完整玩法（自己的场景、表现、音频与输入），但没有存档/读档/设置/历史界面。
  存档变量与档案变量在主/副窗口之间共享，对白历史按发生顺序合并。
- 副窗口绑定到拥有它的运行时（主线或重演），随其新游戏、读档、回到标题、场景切换、结束
  而关闭；用户直接关闭副窗口会被阻止。存档同时保存两个窗口与合并历史。

完整的窗口所有权与合并规则见 `game/README.md` 的 “Secondary window” 一节。

编辑器校验：未选择场景、指向未声明的场景、或 `next` 节点不存在时，会在「问题」面板
报出 `missing_window_scene`、`unknown_window_scene`、`missing_next_node`；目标场景不是副窗口
用途报 `window_scene_not_secondary`，在副窗口专用场景里使用本节点报 `secondary_opens_window`。
重命名场景会自动更新 `open_window` 的目标（与 `jump` 相同）。

#### 窗口与场景用途

- 每个场景要么是**主窗口专用**（默认，旧场景不需要改动），要么是**副窗口专用**，不存在“两边都能用”的场景。
- `open_window` 只能由主窗口场景指向副窗口场景；副窗口不能再打开窗口。
- `jump` 与按钮的「跳转剧情节点」只能在**相同用途**的场景之间跳转。
- 项目入口场景和章节地图热点不能指向副窗口专用场景（章节地图的场景列表也不会列出它们）。
- 副窗口专用场景仍然可以在编辑器里单独选中、预览和编辑。
- 把场景的用途改掉不会擅自改写引用它的节点：不再合法的 `open_window`、`jump`、入口会在「问题」面板里以
  `window_scene_not_secondary`、`window_role_mismatch`、`secondary_entry_scene`、`map_scene_secondary` 逐条列出。
  旧项目里已有的 `open_window` 目标需要补一次「设为副窗口专用」，运行时不会替你猜用途。

**`window_title` 设置窗口标题**

| 字段     | 说明                                                  |
| -------- | ----------------------------------------------------- |
| 目标窗口 | 主窗口 / 副窗口，两个窗口都可以改对方或自己的标题     |
| 标题     | 文本，可含 `[var=变量名]`；执行到这里时求值一次并保存 |
| 下一节点 | —                                                     |

- 标题按**纯文本**写到系统窗口标题栏，不处理排版标记；不超过 4096 字节，不能含控制字符。
- 内置两个**只读字符串变量**：`window.main.title`、`window.secondary.title`。它们可以写进文本
  （`[var=window.main.title]`）、出现在条件和「设置变量」的操作数里；**不能**用「设置变量」去改，
  也不能在变量面板里声明同名变量（`readonly_window_variable`、`reserved_window_variable`）。标题只能由
  `window_title` 节点修改。
- 副窗口不存在时 `window.secondary.title` 为空文本；副窗口创建时用默认标题，被替换或关闭后重置。
  存档会恢复两个窗口当时的标题。
- 先改名、再让对白引用标题，顺序就是节点顺序：同一条链上，`window_title` 之后的对白读到的就是新标题。

**`window_control` 窗口控制**

| 字段     | 说明                                                       |
| -------- | ---------------------------------------------------------- |
| 目标窗口 | 主窗口 / 副窗口                                            |
| 操作     | 阻挡翻页 `block` / 解除阻挡 `unblock` / 推进一页 `advance` |
| 阻挡 ID  | block、unblock 必填；`advance` 不使用                      |
| 提示文本 | 仅 block，可选，可含 `[var=…]`，变量变化时会自动刷新       |

- **阻挡只限制翻页**（手动点击、自动、快进、按钮的「继续」）。选项、其他按钮、计时器照常工作；还没打完的文字
  仍可以点一下显完。被阻挡时，两个窗口都会显示提示文本。
- 一个阻挡由「创建它的场景 + ID + 目标窗口」标识：同一场景用同一个 ID 再 block 会覆盖旧提示；
  `unblock` 只解除**自己用这个 ID 创建**的阻挡，不会误清别的原因造成的阻挡。创建阻挡的场景退出、
  或目标窗口被替换时，阻挡会自动清除，不会遗留锁。
- `advance` 是一次**脚本驱动的翻页**：不替玩家选择选项，不会跳过正在播放的表现，也不会偷偷解除阻挡——
  需要先 `unblock`，再 `advance`。目标窗口当时不在对白或长文本上时不会推进，也不会排队留给之后的对白。
  脚本推进不受玩家自动/强制自动设置限制。
- 目标窗口不存在时（例如没有打开副窗口），宿主会给出明确诊断，整条命令不产生部分修改。

**`window_geometry` 窗口位置/大小**

| 字段          | 说明                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------ |
| 目标窗口      | 主窗口 / 副窗口                                                                            |
| 改变位置      | 开关。位置和大小**至少要改变一项**，否则报 `invalid_window_geometry`                       |
| 位置预设      | 屏幕居中、屏幕四角与四边、贴在另一窗口的右/左/上/下侧、相对当前位置偏移、自定义            |
| 参考对象      | 屏幕工作区（默认）/ 另一个游戏窗口 / 自身当前位置                                          |
| 参考点 X、Y   | 参考对象上的比例点：0 为左/上边缘，1 为右/下边缘；范围 −4…4，超出 0…1 表示落在参考对象之外 |
| 窗口锚点 X、Y | 窗口外框上用来对齐的点，0…1；0.5 / 0.5 是窗口中心                                          |
| 偏移 X、Y px  | 对齐之后再平移的逻辑像素，不超过 ±10000                                                    |
| 改变大小      | 开关                                                                                       |
| 大小单位      | 逻辑像素（窗口客户区，不含标题栏和边框，1–10000）/ 工作区比例（含边框，大于 0 且不超过 1） |
| 宽度、高度    | 按所选单位填写；切换单位会重置为该单位的默认值（960×540 / 50%×50%）                        |
| 时长 ms       | 0–60000；**0 为瞬间到位**                                                                  |
| 缓动          | 线性 / 缓入 / 缓出 / 缓入缓出（默认）                                                      |
| 等待完成      | 勾选且时长大于 0 时，剧情等动画播完再继续                                                  |
| 下一节点      | —                                                                                          |

- **定位模型**：窗口上的「锚点」被放到参考对象上的「参考点」处，再平移「偏移」。例如「屏幕居中」是参考点 (0.5, 0.5)
  加锚点 (0.5, 0.5)；「贴在另一窗口右侧，留 16 像素间距」是参考对象为另一个游戏窗口、参考点 (1, 0.5)、锚点 (0, 0.5)、
  偏移 X 16。**预设只是替你填好这些数字**：选完以后每一项仍可微调，改到不再匹配任何预设时下拉显示为「自定义」；
  预设的判断不看偏移，所以把间距从 16 改成 24 仍然是「贴在另一窗口右侧」。
- **三种参考对象**：「屏幕工作区」是窗口所在显示器去掉任务栏后的区域；「另一个游戏窗口」对主窗口来说是副窗口，
  对副窗口来说是主窗口（摆放前请先用「打开副窗口」把它开出来）；「自身当前位置」以窗口此刻的外框为参考，
  参考点 (0, 0) 加锚点 (0, 0) 再填偏移就是纯粹的相对移动（预设「相对当前位置偏移」）。
- 位置和大小在**同一个节点**里一起动画；只填其中一项就只改那一项。窗口始终被限制在所在显示器内，不会被推到屏幕外；
  主窗口最小 960×540，副窗口最小 480×270（逻辑像素）。逻辑像素尺寸小于这个下限时，检查器会提示「运行时会被放大到最小尺寸」，
  但不算错误。
- **全屏或最大化的窗口会跳过移动和缩放**（不报错）。
- **存档不记录窗口位置和大小**。回到标题或退出章节重演时，主窗口会自动恢复到原来的位置和大小；副窗口随副窗口一起关闭。
- **动画**：时长为 0 是瞬移；「等待完成」只在时长大于 0 时才让剧情等待。没有勾选「等待完成」的节点可以作为**计时器目标**
  反复触发，用来做漂移、抖动之类（见 17.12）；勾选了「等待完成」的节点不能作为计时器目标（`invalid_timer_target`）。
- 校验：位置/大小越界或一项都没设置报 `invalid_window_geometry`，时长超出 0–60000 报 `invalid_duration`，
  目标窗口不是主/副窗口报 `invalid_window_target`。
- **预览不会移动或缩放真实窗口**：单场景预览是编辑器自己的窗口，遇到本节点只会在画面上方提示
  「预览不会移动或缩放真实窗口……请在桌面运行验证」，不会假装成功；要看效果请在桌面运行游戏。

**`window_layer` 窗口层级**

| 字段     | 说明                                                 |
| -------- | ---------------------------------------------------- |
| 目标窗口 | 主窗口 / 副窗口                                      |
| 层级操作 | 提到最前 / 聚焦 / 置顶 / 置底 / 恢复普通层级（见下） |
| 下一节点 | —                                                    |

| 操作                 | 值       | 效果                                                           |
| -------------------- | -------- | -------------------------------------------------------------- |
| 提到最前（不抢焦点） | `raise`  | 把窗口放到其他窗口上方，但**不**激活它，键盘焦点留在原来的窗口 |
| 聚焦（抢焦点）       | `focus`  | 激活窗口并**抢走键盘焦点**；玩家正在别处输入时会被打断，慎用   |
| 置顶                 | `top`    | 窗口始终在其他应用上方，直到「恢复普通层级」                   |
| 置底                 | `bottom` | 窗口始终在其他应用下方，直到「恢复普通层级」                   |
| 恢复普通层级         | `normal` | 取消置顶/置底，回到普通窗口层级                                |

- 本节点总是可以作为**计时器目标**。
- 层级操作用到一个原生窗口，所以**预览不会改变真实窗口层级**，会在画面上方提示「预览不会改变真实窗口层级……请在桌面运行验证」。
- 层级操作不合法时报 `invalid_window_layer_action`，目标窗口不合法报 `invalid_window_target`。

**`timer` 计时器**

| 字段                 | 说明                                               |
| -------------------- | -------------------------------------------------- |
| 操作                 | 启动 `start` / 停止 `stop`                         |
| 计时器 ID            | 场景内唯一标识；同 ID 再次启动会替换旧计时器       |
| 首次延迟 ms          | 0–60000                                            |
| 重复触发             | 勾选后填重复间隔（≥ 50 ms，≤ 60000）；不勾选为单次 |
| 触发时运行的效果节点 | 同一场景里的一个效果节点（见下）                   |
| 下一节点             | 计时器自己的后续；启动后主线立刻继续               |

- 到点只运行**目标节点自己的效果**，**不会**沿它的「下一节点」往下走，也不会改变正在等待的对白、长文本或选项。
  所以目标节点通常放在主线之外，它的「下一节点」只是一个占位。
- 可选的目标：设置变量、音效、窗口标题、窗口控制、窗口层级，以及**没有**开启「等待完成」的窗口位置/大小、背景、立绘、立绘动作、时间线、
  BGM、环境声、镜头、屏幕效果、幕布、UI 动效播放。需要组合动画请用时间线节点。
  对白、选择、跳转、等待、结束、打开副窗口、计时器、清除画面、UI 显隐等会改变主线或再次调度的节点不可选；
  下拉里只列合法目标，选了不合法的会报 `invalid_timer_target` / `missing_timer_target`。
- 剧情图上，计时器节点多一个**虚线**的「触发效果」出口，连到它的效果节点；这条线是引用，不是主线流程。
  重命名效果节点会同步更新引用；删除效果节点会清空引用（不会误接到流程节点上）并报缺少目标；
  复制/粘贴一组节点时，组内的计时器会指向复制出来的效果节点，单独粘贴计时器则清空目标让你重新选择。
  只被计时器引用的效果节点不会被报为「无法到达」，但它的后续节点不会因此变成可到达。
- 重复计时器不会叠加：上一次效果还在播放时不会重叠触发，卡顿后错过的周期合并为一次，不会补发一堆。
  同时活动的计时器最多 64 个；效果出错时该计时器会被停止并给出诊断。
- **生命周期：计时器不会自己结束。** 它会一直运行，直到被 `stop` 节点停止、场景退出或会话结束
  （新游戏、读档、回标题、重演切换同样会清掉旧计时器）。典型用法是等待动画：在等待处之前启动重复计时器，
  在离开等待处的后续节点里**显式停止**。普通的循环帧图仍然用帧动画素材，不必改成计时器。
- 打开存档/设置/历史面板时剧情计时暂停；只是把焦点从主窗口切到副窗口不会暂停。
- 编辑器里的单场景预览会在本窗口内真正运行计时器、标题和阻挡（见 5.7）；
  **对另一个窗口的请求**（改标题、阻挡、推进、打开副窗口）以及窗口位置/大小、窗口层级在预览里不会生效，预览会明确提示
  「预览是单窗口……请在桌面双窗口运行验证」，不会假装成功。要验证两窗口联动，请用桌面双窗口运行游戏。

### 7.5 画面节点

**`background` 背景**

| 字段                      | 说明                                                                                     |
| ------------------------- | ---------------------------------------------------------------------------------------- |
| 背景素材                  | 必须是 background 类型（可为空）                                                         |
| 转场类型                  | 直接切换 cut / 交叉淡化 cross_fade / 淡过颜色 fade_through_color / 划像 wipe / 推入 push |
| 方向                      | 仅在 wipe / push 时出现，四向可选（从左到右 / 从右到左 / 从上到下 / 从下到上）           |
| 中间颜色                  | 仅在 fade_through_color 时出现，`#RRGGBB` 或 `#RRGGBBAA`                                 |
| 软边（0–1）               | 仅在 wipe / push 时出现，默认 0                                                          |
| 时长 ms / 等待完成 / 缓动 | AnimationFields；缓动对 cross_fade 生效                                                  |
| 下一节点                  | —                                                                                        |

检查器下方是共享 `SceneSurface` 的背景转场预览：`播放` 走真实转场，`转场前 / 转场后`
与进度滑杆可以确定性定位到任意时刻（同一参数与同一时刻总是同一帧），预览静音、可取消。

**`curtain` 幕布**

| 字段                      | 说明                                                                                         |
| ------------------------- | -------------------------------------------------------------------------------------------- |
| 幕布动作                  | cover 落下 / reveal 收起                                                                     |
| 幕布填充                  | 仅 cover 出现：颜色（`#RRGGBB(AA)`）或已登记的 `gui` 素材；reveal 隐藏当前幕布，不能指定填充 |
| 幕布动画                  | fade / wipe（四向划像）/ split_horizontal（水平对开）/ split_vertical（垂直对开）            |
| 时长 ms / 等待完成 / 缓动 | AnimationFields                                                                              |
| 下一节点                  | —                                                                                            |

幕布是位于世界之上、屏幕效果之下的持续图层；只有稳定状态（是否覆盖与填充素材）会进入存档，
动画参数只存在于本次 cue。检查器内嵌 1920×1080 的共享 `SceneSurface` 实时预览，
可以确定性定位与回放。

**`sprite` Sprite（背景 / 角色 / 物品 / 独立 UI / 文本）**

| 字段                           | 说明                                                                 |
| ------------------------------ | -------------------------------------------------------------------- |
| 实例 ID                        | 场景内唯一，后续 `action`、时间线都引用它；`__background__` 为保留 ID |
| 动作                           | 显示 show / 移动·修改 move / 隐藏 hide                               |
| Sprite 来源                    | 「继承 / 角色表情 / 旧素材」，或统一图片来源（background/sprite/gui 均可），或固定文本块 |
| Sprite 类别                    | 背景 / 角色 / 物品 / 独立 UI / 固定文本：只决定新实例的默认值，不重置已有姿态 |
| 坐标空间                       | 世界（随镜头、震动与着色器）/ 屏幕（固定在画面上）                   |
| 布局框                         | 可选宽、高与 完整包含 / 覆盖 / 拉伸                                  |
| 横向/纵向缩放、旋转、锚点      | 留空表示继承当前值                                                   |
| 角色绑定                       | 可选；绑定后可用「表情」                                             |
| 表情                           | 角色声明的表情；未绑定角色时不出现                                   |
| 立绘素材                       | 未绑定角色时必选；绑定角色后由表情素材自动提供，也可保留一个可选覆盖 |
| X / Y / 缩放 / 透明度 / 层级 Z | 默认 960 / 1080 / 1 / 1 / 0                                          |
| 水平翻转                       | move 时是「保持当前 / 不翻转 / 翻转」，其余情况是勾选框              |
| 换表情淡化 ms                  | 表情切换的交叉淡化                                                   |
| 时长 / 等待 / 缓动 + 下一节点  | AnimationFields                                                      |

选择统一来源后，角色绑定与表情字段会隐藏（两者互斥）。检查器下方的舞台预览来自运行时的真实结果，
拖动目标即可写回 X / Y；屏幕空间对象按画面坐标移动，世界对象会扣除镜头变换。

**`particle` 图片粒子**

| 字段                         | 说明                                                                     |
| ---------------------------- | ------------------------------------------------------------------------ |
| 发射器实例 ID                | 后续 stop、时间线「发射器整体轨」都引用它                                |
| 粒子动作                     | 持续发射 / 重启 start、停止并清除 stop、单次爆发 burst（不存档、读档不重放） |
| 粒子效果                     | start / burst 必选，引用「粒子效果」库中的定义                           |
| 随机种子                     | 留空沿用定义里的种子                                                     |
| 坐标空间                     | 世界 / 屏幕                                                              |
| X / Y / 整体缩放 / 旋转 / 透明度 / 层级 Z | 只作用于整个发射器                                         |

新建、插入或切换为粒子节点时，编辑器自动分配未占用的发射器实例 ID（如 `emitter`、`emitter_2`），
因此多个持续特效可以同时存在。同 ID 的 `start` 表示重启同一个发射器，`stop` 只清除该 ID；
复制或粘贴持续发射节点也会分配新实例 ID（如 `snow` → `snow_2`），避免覆盖原效果。
同组复制的重启、停止节点和发射器时间线轨道会同步引用新 ID；只复制停止节点或轨道时则保留原目标。
已有剧情不会自动改写 ID；需要主动重启某个实例时，仍可手动使用它的 ID。
粒子节点不阻塞剧情，也可以作为计时器的效果目标。持续发射器进入存档，读档后按种子从头开始；
单个粒子不能被选择、拖动或建立轨道。

**`clear` 清除画面**：淡出背景、立绘、镜头与持续视觉（包括持续粒子），保留 BGM 和对话框；带 AnimationFields。

**`camera` 镜头**：X、Y、缩放、AnimationFields。

**`screen_effect` 屏幕效果**：效果类型 = 闪光 / 震动 / 色差 / 故障 / 冲击波 / 色彩修正 / 聚焦模糊 / 波纹。

- 闪光：颜色（`#RRGGBB(AA)`）、峰值透明度（0–1）；
- 震动：横向振幅 / 纵向振幅（0–256）、频率 Hz（0.1–60）、衰减（0–1）、seed（0–4294967295 的整数）；
- 色差：强度 px（0–128）、方向角度（-360–360）、中心 X / Y、边缘权重（0 = 全屏均匀偏移，1 = 中心无偏移、越靠边越强）、渐入 / 渐出比例；
- 故障：位移 px（0–512）、切片数（1–32）、切片密度（0–1，每一步有多少横条错位）、变化频率 Hz（0.1–60）、seed、渐入 / 渐出比例；
- 冲击波：中心 X / Y、最大半径 px（1–4096）、波宽 px（1–1024）、扭曲强度 px（0–256）；圆环从中心扩散到最大半径，强度随之衰减；
- 色彩修正：亮度偏移（-1–1，直接加在 RGB 上）、对比度（0–2，围绕中灰 0.5）、饱和度（0–2）、着色颜色（`#RRGGBB(AA)`）、着色强度（0–1）、效果强度（0–1）、渐入 / 渐出比例；默认是中性（亮度 0 / 对比度 1 / 饱和度 1 / 不着色），此时不安装滤镜；
- 聚焦模糊：中心 X / Y、清晰半径 px（0–2203）、边缘过渡 px（1–2203）、最大模糊 px（0–24）、边缘压暗（0–1）、效果强度、渐入 / 渐出比例；半径内保持清晰，过渡带之外才开始模糊并压暗，模糊是有限抽头的可分离高斯（艺术化近似，不是景深）；
- 波纹：中心 X / Y、振幅 px（0–64）、波长 px（8–2203）、速度 px/s（0–2000）、衰减（0–8）、效果强度、渐入 / 渐出比例；从中心向外扩散的周期性同心位移，与冲击波的单个扩张圆环不同；
- 时长 + 等待完成；检查器内嵌与背景相同的共享 `SceneSurface` 预览。

固定 seed 保证游戏、编辑器预览与任意 seek 位置得到完全一致的震动和故障图案；节点与时间线事件使用
同一结构。渐入 / 渐出比例是占效果时长的比例，两者之和不能超过 1（例如渐入 = 1 表示整段逐渐增强）。

色差、故障、冲击波、色彩修正、聚焦模糊与波纹是着色器效果，**只作用于场景画面**（背景、立绘、视频）；对白框、选项、按钮、幕布和闪光不会被扭曲。
不同类型的效果可以同时叠加，固定按「波纹 → 冲击波 → 故障 → 色彩修正 → 聚焦 H/V → 色差」的顺序处理；同一类型重叠时以较晚开始的为准。效果强度为 0（或恒等色彩修正 / 模糊与压暗都为 0）时不安装任何滤镜，与删除该效果逐像素等价。
玩家在游戏设置里开启「减弱动态效果」后，闪光亮度被限制、震动与着色器效果强度降低、故障跳变速度放慢，波纹被关闭、聚焦模糊被关闭（如有边缘压暗则保留）。

**`timeline` 关键帧时间线**

| 字段           | 说明        |
| -------------- | ----------- |
| 时间线时长 ms  | 1–1800000   |
| 等待时间线完成 | `await`     |
| 允许手动跳过   | `skippable` |
| 下一节点       | —           |

检查器提示「双击时间线节点进入全屏工作区」。

**`dialogue_ui` 对话框**：显示对话框（显示/隐藏）、本次动效（可「使用当前默认绑定」或指定 UI 动效）、时长覆盖、等待动效完成、下一节点。

**`ui_motion_set` 设置 UI 动效**：默认槽位（对话框出现 / 对话框收起）、后续默认动效、下一节点。

**`ui_motion_play` 播放 UI 动效**：播放动效、时长覆盖、等待动效完成、下一节点。

### 7.6 交互节点（按钮）

**`button_create` 创建按钮**

| 字段       | 说明                                                                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 实例 ID    | 后续 update / remove / 时间线按钮轨引用                                                                                                   |
| 按钮模板   | `id · 宽×高`                                                                                                                              |
| 布局       | X、Y、宽度、高度、旋转°、横向缩放、纵向缩放、透明度、层级 Z、显示、启用点击                                                               |
| 点击行为   | 变量修改（sets）+ 点击后操作：无（仍拦截背景点击）/ 推进剧情 / 跳转剧情节点（可选场景与目标节点）/ 打开系统面板（存档 / 设置 / 历史记录） |
| 节点完成后 | 下一节点                                                                                                                                  |

**`button_update` 更新按钮**：实例 ID、替换模板（可选）、布局覆盖、点击行为（可选）、节点完成后。

**`button_remove` 移除按钮**：实例 ID、下一节点。

### 7.7 声音节点

**`bgm`**

| 字段                       | 说明                                                             |
| -------------------------- | ---------------------------------------------------------------- |
| 动作                       | 开始 / 停止                                                      |
| BGM 素材                   | bgm 类型                                                         |
| 音量                       | 0–1，步进 0.05                                                   |
| 起播 ms                    | 从音频的哪个位置开始                                             |
| 自定义循环段               | 勾选后填写循环起点/终点 ms（默认 0 / 素材时长，时长未知时 1000） |
| 时长 / 等待完成 + 下一节点 | 循环点顺序无效、起止点必须同时提供等会被校验拦下                 |

循环点必须同时提供（Schema 校验），且起点小于终点：不填时使用浏览器对
整文件的**原生循环**；填写后按自定义起止点循环，边界由 `timeupdate`
事件驱动：它会在循环终点前 25 ms 提前回绕，但事件本身的触发间隔由浏览器
决定，可能远大于 25 ms 并越过终点，因此并非逐样本精确；当循环终点落在
素材末尾、`timeupdate` 不再触发时，还会用 `ended` 事件把播放头拉回循环
起点并恢复播放。更换素材只交叉淡化当前总线；**同一素材再次以 `start`
更新时保留当前播放相位**，只更新音量、循环点与循环元数据，而 `start_ms`
只在元素首次开始时生效——要让同一素材从另一个起点重新开始，请改用单独
节点或先停止。

`action: start` 的 BGM / 环境声节点在检查器中会显示「波形与循环点」
编辑器，可直接在波形上拖动三个标记，也可以精确填写毫秒整数：

- **起播标记**（`start_ms`）：范围 `0 .. 循环终点`；未启用自定义循环时
  以素材时长为上界。
- **循环起点 / 终点标记**（`loop_start_ms` / `loop_end_ms`）：始终保证
  `loop_start_ms < loop_end_ms`（最小间隔 1 ms），终点不早于 `start_ms`。
- 拖动在松手时只提交**一次**历史记录；拖动过程中的位置是本地草稿，数值
  不会被像素吸附，也不会强制取整到 100 ms。方向键左右各移动 10 ms，
  `Shift` + 方向键移动 1 ms。
- 波形只用于显示与定位：编辑器要求**先确定素材时长与声道数**（宿主
  `metadata.duration_ms` / `channels`；时长缺失时用 `preload="metadata"` 的
  `<audio>` 探测，最长 3 秒，而 `preload` 只是浏览器提示、并不保证只读取
  文件头，所以探测本身也有时限，且探测无法提供声道数），并在下载前用
  时长、声道数与采样率估算解码成本——采样率取**解码器目标采样率
  （44.1 kHz）与输入采样率中的较大值**，因为解码会重采样，低采样率素材
  不会因此缩小预算——拒绝超过 20 分钟或约 256 MiB 解码内存的素材。
  **无法确定时长或声道数时不会下载或解码**，直接显示「波形不可用」——
  压缩字节数无法证明解码后的形状。确定后才会**流式**读取音频，一旦超过
  24 MiB 就立即取消读取（不会先把整个文件读进内存），且没有任何“先读完
  整包”的退回路径。上面任一失败都只影响波形，数值编辑与试听仍然可用，
  绝不会改动已保存的毫秒值；素材时长未知时禁用拖动，只保留数值输入。
- 试听使用独立的临时音频元素，不经过共享音频总线：**只会在你点击试听
  按钮时发声**（预览不会自动播放）。在波形上点击只定位播放头，不自动
  播放：光标不在起播点时按钮会显示为「继续试听（N ms）」并从该位置继续，
  自然播放到素材末尾后光标会复位，下一次点击从起播点重新开始。暂停后
  再点击继续会沿用原来的模式（循环试听仍是循环、一次性试听仍是一次性）；
  「停止」会清空光标与暂停位置，下一次点击从起播点重新开始一次性试听。
- 「整段循环试听」从 `loop_start_ms` 开始完整循环；「接缝试听」从
  `max(loop_start_ms, loop_end_ms - 1500)` 开始，让第一次循环接缝立即
  出现，随后同样回绕到 `loop_start_ms`。两者都只在起止点都有效时可用；
  回绕由 `timeupdate` 驱动，同样只在循环终点前 25 ms 提前触发，事件间隔
  由浏览器决定、可能越过终点，因此是粗粒度而非逐样本精确。修改循环起止点
  （拖动、数值输入或撤销/重做）不会打断试听：同一个音频元素继续播放，
  仍在原来的位置；新边界在下一次边界检查时生效——光标已经越过新终点就
  回绕到新起点，而新循环段完全在光标之后时不会立刻跳转，先把这段空隙
  播完再回绕。关闭「自定义循环段」的循环试听会转为整文件原生循环（不会
  重新开始）；一次性试听始终是一次性，不会被后来出现的循环点变成循环。
  切换节点或素材、关闭检查器都会停止并释放该元素。

**`ambience` 环境声**

环境声使用独立的四槽位总线：`slot_1`、`slot_2`、`slot_3`、`slot_4`。
`start` 必须选择 `kind: ambience` 的素材，`stop` 不填写素材，只停止当前
槽位。音量、起播位置、可选循环起止点、波形与循环点编辑器、试听和淡化
时长与 BGM 一致；同一素材替换时保留播放相位（`start_ms` 只在首次开始时
生效，只更新音量与循环点），不同素材只交叉淡化当前
槽位。场景切换、读档、取消预览和失败加载都会由共享音频所有者清理旧传输。

时间线可为每个槽位添加一条 `ambience` 轨道，轨道只支持 `volume` 通道，
同一槽位不能重复。播放结束后会恢复快照中的槽位音量，不能把环境声状态
写入 `SceneFrame` 或 Pixi 对象。编辑器预览默认静音；点击「声音」后才会
激活 Web Audio。游戏和编辑器都可通过共享只读 `AudioDiagnostics` 查看四个
槽位的素材、音量、相位、暂停状态和 ambience bus，不可直接修改媒体元素。

`game/scenes/ambience_lab.yaml` 已在章节地图中提供四通道可达示例：同时
启动四个槽位、独立自动化、先对 slot 2 做同素材保留播放头的 retune，再做跨素材
替换，最后停止 slot 3/4。四个示例素材由仓库内确定性生成器创建（运行
`npm run assets:ambience` 可重建）；其它历史录音仍按 `game/assets/THIRD_PARTY.md`
单独记录来源与发行限制。

**`sfx` 音效**：音效素材、音量、下一节点。

### 7.9 文本标记速查（`say` / `long_text` 通用）

| 写法                                | 含义                                                      |
| ----------------------------------- | --------------------------------------------------------- |
| `$...$`                             | 行内公式                                                  |
| `$$...$$`                           | 独立公式（按视觉基线分组）                                |
| `[var=变量ID]`                      | 变量插值；正文里替换为文字，公式里只接受 integer / number |
| `[pause=500ms]`                     | 硬性揭示边界：之前所有动画和暂停完成前，后续内容不开始    |
| `[speed=30cps]` / `[speed=default]` | 局部速度覆盖                                              |
| `[auto]`（放句末）                  | 文字、公式动画和 pause 完成后立刻推进                     |
| `[fx=shake]...[/fx]`                | 文本效果：shake / wave / glow                             |
| `\$`、`\[`、`\\`                    | 转义                                                      |

HTML 和脚本永远不会被解释。编辑器会把未声明的插值变量、公式里不兼容的插值类型标成错误。

## 8. 长文本（long_text）与全屏工作区

「长文本」是 `say` 的全屏替代方案，用于数学讲解、黑板推演：玩家每点一次推进一段，已写出的内容会留在同一张纸上，可以跨节点继续。

### 8.1 核心概念

| 概念               | 说明                                                                         |
| ------------------ | ---------------------------------------------------------------------------- |
| 文稿（document）   | 一份长文本的身份；默认等于节点 ID，可用 `文稿 ID` 显式指定                   |
| 模式               | 开始新文稿 / 接续已有文稿                                                    |
| 离开行为 `on_exit` | 关闭文稿（默认）/ 隐藏但保留 / 继续显示                                      |
| 分页 `pagination`  | 连续长卷 / 自动分页（默认）/ 仅手动分页                                      |
| 步骤 `steps`       | 每个步骤对应一次玩家推进；每步有稳定且唯一的 ID                              |
| 纸张 `paper`       | 可选 gui 素材；不选则完全透明，适合板书                                      |
| 布局 `layout`      | 1920×1080 设计像素下的 X / Y / 宽 / 高 / 水平边距 / 垂直边距 / 页高 / 页间距 |

规则要点：

- 开始节点拥有纸张、分页、字号、颜色、布局；接续节点**不能重复定义**这些字段，运行时继承开始节点。
- 自动分页按**测量后的视觉行**换页，不拆开一条公式；一个很长的步骤可以跨页。
- 仅手动分页只在作者添加的分页标记处换页，超出的单页向下扩展；连续长卷不能使用强制分页。
- 存档只保存已写出的步骤，不保存滚动位置和打字动画。
- 开始节点被接续/控制节点引用时不能删除；文稿必须有且只有一个开始节点。

### 8.2 在检查器里编辑步骤

检查器的「推进段落」区域：

- 每段有 `步骤 ID`、`文本`（支持与 `say` 相同的标记）、`从新纸张开始`（即 `page_break_before`）；
- 「添加推进段落」新增；段落可 `↑ / ↓` 排序、删除；
- 「从此处分成接续文稿」从第二段起可用；
- 「在光标处分段并接续」在光标处把对话拆开。

### 8.3 全屏工作区

从检查器点「全屏背景预览编辑」，或双击剧情图中的 `long_text` 节点进入。界面：

- 顶栏（统一顶栏）：`返回剧情图`、`长文本  节点 ID`、播放控制组（`播放预览`/`暂停预览`、`补全`、`下一分段`、`从头重播`、「第 N / M 段」）、`撤销`、`重做`、保存状态、`保存`。
- 左侧：1920×1080 设计舞台，直接渲染游戏同一份共享 `LongTextPanel`（纸张、测量根、分页器、揭示时钟与滚动控制器都是同一实现）；滚轮或拖动即可滚动累计文稿。编辑用的布局框只通过顶部标签条移动、右下角手柄缩放；默认 **10px 吸附**，按住 `Shift` 取消吸附。
- 右侧分区：`预览与布局`、`同文稿节点`、`文本区域（设计像素）`、`当前节点步骤`。

右侧可改字段：

| 字段                 | 取值                                                                                                                |
| -------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 当前背景（仅编辑器） | 自动 / 无背景 / 各 background 素材；**只影响编辑预览，不写入 YAML**                                                 |
| 纸张素材             | 透明板书 或 gui 素材；接续节点禁用                                                                                  |
| 字号                 | 设计像素，≥16（校验范围 16–72）                                                                                     |
| 正文颜色             | `#RRGGBB` 或 `#RRGGBBAA`                                                                                            |
| 分页方式             | 连续长卷 / 自动分页 / 仅手动分页                                                                                    |
| 文本区域             | X(0–1920)、Y(0–1080)、宽(160–1920)、高(240–1080)、水平边距(0–480)、垂直边距(0–480)、页高(240–10000)、页间距(0–1000) |

接续节点上，纸张 / 分页 / 字号 / 颜色 / 布局为禁用状态，需要回到开始节点修改。

### 8.4 真实预览

工作区使用与游戏完全相同的 `@vectspace/text` 标记解析、KaTeX 配置、视觉行分页和揭示时钟，并直接渲染游戏同一份共享 `LongTextPanel`（共享 `TextRevealSession`）。预览通过 Rust 运行时从**当前 Scene 入口**构造进入状态，只重放本 Scene 内到达该节点之前的分支选择；如果路径不通会显示「无法到达目标节点」「真实预览需要先选择 scene/node」等诊断。预览路径选择保存在编辑器布局里，不影响玩家存档。

### 8.5 拆分与限制

- 拆分点必须是第二段及之后（`只能在第二段及之后拆分长文本。`）。
- 拆分后第一段自动设为「继续显示」，接续段不重复定义样式字段。
- 步骤数限制 1–1024；有强制分页的第一段不能在文档开头出现，连续长卷不能使用强制分页。

## 9. 关键帧时间线工作区

### 9.1 概念

时间线节点在一段显式时长内播放多条轨道。每条轨道是一个目标对象（立绘 / 镜头 / 视频 / BGM / 环境声 / 按钮）的若干**通道**，每个通道是一串关键帧：

```text
{ at_ms, value, easing }   # easing 控制从本帧到下一帧的过渡
```

缓动预设：step、linear、ease_in、ease_out、ease_in_out；自定义曲线用 `cubic_bezier`（在检查器里有 4 个 Bezier 数值输入和曲线预览）。

**支持 6 类轨道**（没有字幕轨）：

| 轨道              | 通道                                                            |
| ----------------- | --------------------------------------------------------------- |
| 立绘轨 sprite     | x, y, scale, scale_x, scale_y, rotation_deg, opacity, z         |
| 镜头轨 camera     | x, y, zoom, rotation_deg                                        |
| 按钮轨 button     | x, y, width, height, scale_x, scale_y, rotation_deg, opacity, z |
| 视频轨 video      | x, y, width, height, opacity, z, volume                         |
| BGM 轨 bgm        | volume                                                          |
| 环境声轨 ambience | slot_1–slot_4；volume                                           |

立绘轨专属字段：`Sprite ID`、素材（`继承进入时素材` 或具体素材）、`结束后移除`。
视频轨专属字段：`裁剪起点`、`裁剪终点`（留空到视频结尾）、`适配`（contain / cover / stretch）、`视频声音`、`循环片段`。视频时间线总是等待完成。
非循环视频在**有效片段终点**（显式的裁剪终点，未填写时取素材时长）暂停并保持最后一帧，不会越过终点继续播放、反复回跳或播放尾部声音；终端帧的贴图会在定位到终点的 `seeked` 完成后才刷新，因此媒体落后于播放头时也不会留下旧帧。`循环片段` 的视频在片段内循环，素材自然结束时也会回到片段起点继续。作者单独预览与共享运行时使用同一套片段窗口计算，且预览在媒体元数据加载后会用当前播放头重新对齐（固定播放头的暂停态工作区也不例外）。

### 9.2 进入与顶栏

双击 `timeline` 节点进入（或右键节点 →「打开时间线」）。所有全屏工作区共用同一种顶栏，从左到右依次是：

- `返回剧情图`；
- 工作区类型与对象：`关键帧时间线  场景 / 节点`；
- 本工作区的工具：
  - 播放 / 暂停按钮（`Space`）与 `播放 {} · 起点 {} ms` 读数；
  - **`时长`**：时间线总时长（ms），失去焦点或 `Enter` 时提交；
  - `吸附` 下拉：`10 ms / 50 ms / 100 ms`；
  - `自动关键帧` 开关；
  - 静音按钮（预览默认静音，按钮提示为「取消静音」）；
  - 上下文状态与「重建上下文」按钮；
- 右侧固定：`撤销`、`重做`（不可用时变灰）、保存状态、`保存`。

底部控制条：停止、`选择`、`镜头` 工具；条件出现的 `写入所改通道`；`新建轨道类型` 下拉（立绘轨 / 镜头轨 / 视频轨 / BGM 轨 / 环境声轨 / 按钮轨）；环境声轨另选固定槽位（环境声 1–4）；按钮实例下拉；`＋轨道`、`＋SFX`、`＋闪光`、`＋演出预设…`。

### 9.3 建立真实预览

工作区通过 Rust 的 `RuntimeEngine` 从**当前 Scene 入口**构造进入状态，只询问该 Scene 内到达目标节点之前的分支选项；之后编辑直接在本地重建 cue，不重跑剧情路径（只有切换目标节点会重建上下文）。

右侧检查器：

- `预览上下文`：显示当前进入状态；
- `变量覆盖（JSON）`：临时覆盖变量（无效 JSON 会被拒绝）；
- `请选择预览路径`：当分支无法唯一确定时，向导式选择；预览路径与选择保存在 `layout.timeline_previews[sceneId/nodeId]`，**不写剧情 YAML、不进玩家进度**；
- `对象` 列表（SPR / BTN / VID）、`选中对象`、`选中关键帧` / `选中事件` 编辑区。

### 9.4 对象操作

- 立绘 / 视频 / 按钮对象：拖动移动，角点缩放，顶部旋转；缩放最小 0.05（视频宽高最小 16）；按钮只能用 scale_x / scale_y。
- 按钮对象在舞台预览里直接渲染游戏同一份共享 `TemplateButton`（素材、素材模式、适应模式与状态动画都是同一个组件），位置与尺寸取时间轴在播放头处的求值结果。
- 镜头工具：显示相机 gizmo，可移动、缩放（zoom 下限 0.05）、旋转。
- 舞台是 1920×1080 设计坐标；拖动物体会写相对进入姿态的变换。屏幕空间 Sprite 按画面坐标移动，世界对象扣除镜头变换。
- 对象列表中的 `EMT` 是已启动的持续粒子发射器：选中后只能整体移动、缩放、旋转（没有横向/纵向缩放手柄），拖动会自动创建「发射器整体轨」。单次爆发和单个粒子不会出现在列表里；背景节点生成的 `__background__` 也不出现，要编辑背景请用背景节点，或用 Sprite 节点（类别「背景」）创建自己的背景实例。
- Sprite 轨道可以指定来源（图片 / 固定文本块）、类别、坐标空间和布局框；只在轨道新建实例时套用类别默认值。

### 9.5 关键帧编辑

- **通道行**：每条轨道只显示已有关键帧的通道（通道名为中文，例如「X 位置」「不透明度」），外加轨道头「关键帧通道」下拉当前选中的那一个。要给新通道打帧：在下拉里选中通道，再点「＋关键帧」（写在播放头处）或双击该通道行的空白处。
- 双击通道空白处添加关键帧；时间按吸附网格取整。
- 拖框多选（`Ctrl/⌘` 追加）；选中后可改 `时间`、`数值`、`缓动`。
- 时间尺左侧的图标按钮：复制（`Ctrl/⌘+C`）、粘贴到播放头（`Ctrl/⌘+V`）、删除关键帧（`Delete`）、缩小 / 放大时间轴。粘贴目标不存在或超出时间线时会提示「目标轨道不存在或关键帧超出时间线」。
- **时间轴缩放**：`Ctrl/⌘ + 滚轮` 或放大 / 缩小按钮，1×（整段时长铺满）到 32×；放大后横向滚动查看。时间尺以**秒**标注，刻度密度随缩放自动调整（例如 `0.2s`、`1s`）。
- `值来源` = 固定数值 / 继承入口值；`继承` 只在第 0 帧、非视频轨、且该通道至少有 2 帧时可用，含义是「在 0ms 读取该通道进入时间轴时的真实值」。
- 事件轨道：单击选中并把播放头定位到事件，按 `Delete` 删除（不支持双击删除，避免误删）；`＋SFX`、`＋闪光` 添加事件（闪光默认时长被钳制在 1–200ms）。选中屏幕效果事件后可在检查器里切换为震动、色差、故障、冲击波、色彩修正、聚焦模糊或波纹。
- `＋演出预设…` 在播放头处一次插入一组组合好的屏幕效果事件：**推理断裂**（短促故障 + 轻微色差）、**空间冲击**（冲击波 + 震动 + 弱闪光）、**异常升级**（色差逐渐增强，间歇出现故障）、**修正聚焦**（非中性冷调色彩修正 + 聚焦模糊 + 波纹）。插入后就是普通事件，可逐个调整或删除；超出时间线末尾的部分会被截短或省略。

`选中对象` 里的数值输入（X / Y / Scale / Rotation / Opacity / Z 等）会在输入时立即写关键帧并刷新真实预览，不需要离开再进入工作区：提交后交互式的临时覆盖会被丢弃，语义回到「时间轴在播放头处的求值」，因此继续拖动播放头会按关键帧插值，而不是一直停在刚改过的数值上。

### 9.6 播放、吸附与自动关键帧

- `Space` 播放/暂停；`←/→` 移动播放头 ±10ms。
- 播放头是唯一的预览时钟；视频按播放头 seek（非循环时钳到有效片段终点——显式 `clip_end_ms`，未填写时取素材时长——并在终点暂停保持末帧，循环按片段长度取模、素材自然结束时回到片段起点），BGM 初始音量取自进入快照，预览默认静音。
- 吸附会同时考虑网格和对齐「起点」标记。
- `自动关键帧` 关闭时，改动会进入待写入状态（`pendingTransforms` / `pendingCamera`），点「写入所改通道」提交；退出时如有未写入姿态会询问「写入并返回 / 丢弃并返回 / 取消」。
- `Esc`：先取消进行中的手势、让输入框失焦，都没有时才退出工作区；焦点在输入框里或输入法组字时不会退出。

### 9.7 退出与数据

- 退出前若有未提交的手势或待写入改动，按上面的对话框处理。
- 时间线节点本身（时长、await、skippable、轨道、事件）写回场景 YAML；预览变量覆盖与路径只存编辑器布局。

### 9.8 统一的关键帧界面

剧情时间线、立绘动作、按钮模板和 UI 动效共用同一个关键帧界面（`TimelineSurface`）：同一把时间尺与播放头、同一套走带控件、拖框多选、关键帧拖动、缓动（含 cubic-bezier）检查器、`Delete` 与 `Ctrl/⌘+C` / `Ctrl/⌘+V` 共用一个剪贴板。各工作区只把自己的数据映射成这个中立模型，再折叠回本领域结构：

- 剧情时间线：`TimelineNode` ↔ 中立轨道，保留立绘 / 视频素材选择、环境声槽位与事件轨。
- 立绘动作：复用同一界面并保留相对通道、参数绑定、时长与结束姿态。
- 按钮模板：只写入当前状态页签的 `normal` / `hover` / `pressed` 通道，保留状态贴图、素材模式与适应模式。
- UI 动效：每个目标是一条轨道，保留目标列表 / 顺序与 `UiMotionHost` 的 DOM 预览。

例外的只有**循环帧动画**（素材里的「创建帧动画」）：它仍是有序帧列表（自然排序、拖动排序、逐帧时长、`FrameSequencePreview`），不是关键帧界面；只有「素材选择」这一步会遵守素材隐藏策略。

## 10. 章节地图工作区

章节地图是玩家阅读进度地图的编辑界面。

### 10.1 创建与数据

- 点顶栏「章节地图」进入。项目还没有地图时，编辑器自动创建一张空地图，并把它登记为 `chapter-map.yaml`；初始内容只有入口场景的一个热点。
- 地图定义写入 `game/chapter-map.yaml`：`schema_version`、`width`、`height`、`view_x`、`view_y`、`background`、`decorations`、`hotspots`。

### 10.2 三栏布局

- 顶栏（与其他工作区相同的统一顶栏）：`返回剧情图`、`章节地图 世界地图`；中间是 `网格` 与 `初始视图框` 开关、缩小 / 缩放百分比 / 放大、`适合画布`；右侧是 `校验`、`撤销`、`重做`、保存状态与 `保存`。
- 左栏：
  - `未放置的场景`：每个未放置场景一个 `＋ 场景id` 按钮（全部放置后显示「所有场景都已放置」）；
  - `＋ 添加装饰`；
  - `可拖放素材`：gui / sprite 素材列表（显示素材显示名，下方小字为 ID）；
  - `图层`：`装饰 · id` / `章节 · 标题`，每行可切换显隐（●/○）。
- 中栏：房间画布，可含网格、`初始视图` 框、背景、对象和选中对象的四角缩放手柄。
- 右栏：`地图设置` / `章节热点` / `地图装饰`（随选择变化）；底部显示热点对应 `Scene：id` 与 `内容版本：content_version`。

### 10.3 地图设置（未选中对象时）

| 字段            | 说明                                  |
| --------------- | ------------------------------------- |
| 房间背景        | 无 或 background 素材                 |
| 房间宽度 / 高度 | 最小 1920 / 1080，步进 20；上限 16380 |
| 初始视图 X / Y  | 步进 20                               |

提示：`网格：20px。坐标和尺寸保存为设计像素。`

### 10.4 章节热点

| 字段                   | 说明                                                          |
| ---------------------- | ------------------------------------------------------------- |
| 标题                   | 必填；显示在卡片上                                            |
| Hover 文案             | 可留空；留空时用标题，输入空白可隐藏文字框；≤256 字符         |
| 揭示策略               | 完成后显示 / 始终显示 / 条件显示（条件需要存在 profile 变量） |
| 重演策略               | 完成后可重演 / 始终可重演；后者允许玩家在到达该章节前直接进入 |
| 重演变量覆盖           | 按变量类型设置，用于重演                                      |
| 素材                   | 默认卡片 或 gui/sprite 素材                                   |
| X / Y / 宽 / 高 / 层级 | 20px 网格；不允许超出房间                                     |
| 删除对象               | —                                                             |

一个 Scene 只能有一个热点（重复会被校验拦下）。

揭示与重演是两件事：揭示决定热点是否出现在房间页，重演决定到达前能否进入。把
「始终显示 + 始终可重演」一起设置，等于给这个 Scene 开了一个独立的入口：玩家不必
先走到它，房间页也不会再把它显示成「未完成」。这类热点同时会被视为可达入口，
所以只经由地图进入的 Scene（展示关、附录、调试关）不会再被报「节点无法从入口到达」。
只设其中一项时校验提醒仍然保留：隐藏的热点玩家点不到，锁定在完成后的热点在完成前
也进不去。

### 10.5 地图装饰

`素材`（必填）、`X / Y / 宽 / 高 / 层级`、`删除对象`。装饰不与 Scene 关联。

### 10.6 手势与规则

- 从左栏拖 Scene / 素材到画布（也可以直接从左侧素材面板拖入素材），或点左栏的 `＋`；落点吸附 20px。
- 对象拖动、四角缩放，最小尺寸 20px，不能超出房间。
- 空白处拖拽平移画布。
- **缩放**：鼠标滚轮以指针位置为中心缩放；顶栏的放大 / 缩小按钮以画布中心缩放。缩放范围为「适合画布」比例的 0.25×–4×，顶栏显示当前百分比；`适合画布` 同时重置缩放与平移。
- **键盘**：选中对象后按 `Delete` 删除；方向键按 20px 网格移动，`Shift + 方向键` 一次移动 100px（5 格）。焦点在右栏输入框里时这些键只作用于输入框。
- `初始视图框` 固定 1920×1080，可拖动。
- `Esc`：优先取消字段草稿，其次取消进行中的手势，否则返回剧情图。
- 一次 pointerdown → pointerup 只记一条撤销记录。
- 新对象默认尺寸：热点 280×160（z=10）、装饰 240×180（z=1）；ID 冲突时自动加后缀。

### 10.7 校验

顶栏 `校验` 按钮执行完整校验，通过会提示「章节地图已通过完整校验。」常见错误：

- `房间宽高必须是 20px 网格上的整数（1920–16380）。`
- `房间不能缩小到对象之外：…` / `房间不能缩小到初始视图框之外，请先移动视图框。`
- `Scene 在地图中有多个热点：…`、`章节热点引用未知 Scene`
- `X 会使对象超出房间边界。`、`层级必须是 32 位整数。`
- `章节标题不能为空。`、`Hover 文案不能超过 256 个字符。`

## 11. UI 动效与按钮模板工作区

两者都在活动栏的「资源库」面板里：`UI 动效` 和 `按钮模板` 分组标题旁的 ＋ 新建（输入 ID 时实时校验），每行的铅笔按钮进入全屏工作区，「⋯」菜单里是副本、重命名和移除。

所有全屏工作区（时间线、长文本、章节地图、UI 动效、按钮模板、立绘动作）共用同一种顶栏：左侧 `返回剧情图`，然后是工作区类型与对象 ID，中间是本工作区的工具，右侧固定为（可选的 `校验`）`撤销`、`重做`、保存状态和 `保存`。`Esc` 在没有打开的菜单、进行中的拖拽或聚焦的输入框时返回剧情图。

文件路径规则：ID 只允许字母、数字、`.`、`_`、`-`；动效存 `game/ui/motions/<id 点换下划线>.yaml`，按钮存 `game/ui/buttons/<id 点换下划线>.yaml`。

### 11.1 UI 动效工作区

- 顶栏：`返回剧情图`、`UI 动效  id`、`撤销`、`重做`、`保存`。
- 中央是 1920×1080 预览，直接渲染游戏同一份共享 `DialogueBox`（对话框图片、姓名框、正文、推进标记都是同一个组件、同一套 `UiMotionHost` 目标与动效求值），并配一段示例对话；右侧检查器，底部是与其他工作区共用的关键帧界面（走带、时间尺、关键帧、缓动）。
- 可编辑字段：

| 字段     | 说明                                                        |
| -------- | ----------------------------------------------------------- |
| 预设 ID  | 只读；提示「引用稳定；如需新 ID，请新建预设。」             |
| 时长     | 1–1800000 ms；新建默认 280                                  |
| 添加目标 | 对话框整体 / 对话框图片 / 姓名框 / 正文 / 推进标记          |
| 通道     | offset_x、offset_y、scale_x、scale_y、rotation_deg、opacity |
| 关键帧   | 时间 / 数值 / 缓动（含 cubic-bezier），同共享关键帧界面     |

- 每个目标是一条轨道，可增删；在预览里按住目标拖拽即可写 offset_x / offset_y；轨道上双击添加关键帧，时间对齐到 10ms。
- 快捷键：`Space` 播放/暂停、`←/→` 移动播放头 ±10ms（`Shift` 为 50ms）、`Delete` 删除关键帧、`Ctrl/⌘+C` / `Ctrl/⌘+V` 复制粘贴、`Esc` 返回。

### 11.2 按钮模板工作区

- 顶栏：`返回剧情图`、`按钮模板  id`、`撤销` / `重做` / `保存`；播放 / 暂停在底部关键帧界面的走带控件里（`Space`）。
- 可编辑字段：

| 字段           | 取值                                                                   |
| -------------- | ---------------------------------------------------------------------- |
| 模板 ID        | 只读                                                                   |
| 宽度 / 高度    | ≥1（新建默认 200×80）                                                  |
| 素材模式       | separate「三种独立贴图」/ overlay「正常底图 + 状态覆盖」               |
| 适应模式       | stretch「拉伸」/ contain「适应（完整显示）」/ cover「填充（裁剪）」    |
| 显示点击区轮廓 | 复选框                                                                 |
| 状态页签       | 正常 / 悬停 / 按下，各选一张 gui 或 sprite 贴图（「无（沿用/透明）」） |
| 状态动画       | 「添加状态动画 / 启用状态动画」「清除状态动画」，时长 1–1800000        |

- 预览直接渲染游戏同一份共享 `TemplateButton`（三态贴图、素材模式、适应模式与状态动画都是同一个组件），并用状态页签固定当前预览的状态；预览保持只读，不会触发游戏动作。底部关键帧界面按当前状态页签编辑该状态的 `offset_x` / `offset_y` / `scale_x` / `scale_y` / `rotation_deg` / `opacity`，时间是 10ms 网格，缓动检查器与其他工作区一致。切换页签会同时切到该状态自己的通道与贴图，互不影响。
- 注意：按钮的「禁用」状态和位置 / 尺寸不在模板工作区设置，而是在剧情的 `button_create` / `button_update` 节点里（见 7.6）；hover 文案属于章节地图热点，不在按钮模板里。

### 11.3 在剧情里使用

- 对话框出现/收起：在「资源库」面板的 UI 动效分组里把 `对话框出现` / `对话框收起` 绑定到某个 UI 动效作为默认；单个节点可在 `dialogue_ui` 的「本次动效」里覆盖。
- 手动播放动效：`ui_motion_play` 节点选「播放动效」和时长覆盖。
- 按钮：`button_create` 创建实例 → `button_update` 改布局或行为 → `button_remove` 移除；时间线里还能给按钮实例加按钮轨做位移动画。

## 12. 素材管理

### 12.1 支持的类型

| 类型       | 用途                             |
| ---------- | -------------------------------- |
| background | 背景（含循环帧动画）             |
| sprite     | 立绘、表情、按钮/地图装饰贴图    |
| gui        | 对话框、纸张、按钮贴图等界面素材 |
| bgm        | 背景音乐                         |
| sfx        | 音效                             |
| video      | 视频（H.264 + AAC 的 MP4）       |
| font       | 字体                             |

### 12.2 导入流程

1. 活动栏「素材」面板点 `＋`（可多选文件），或直接把文件拖进面板。
2. 编辑器先检查文件（格式、尺寸/时长、大小、哈希），通过后进入**不透明的暂存会话**。
3. 导入对话框逐行显示并允许修改 `素材 ID`、`类型`、`文件名`，`×` 移除；重复/非法会被就地标错（例如 `ID 只能包含字母、数字、点、下划线或连字符`、`文件扩展名与素材类型不匹配`）。
4. 点确认后素材先暂存在编辑器内，提示「保存项目后才会正式加入项目」；撤销或未保存的导入**不会**进入正式 `game/assets`。
5. 保存项目时，素材与 manifest、Scene、地图一起进入可恢复事务。

### 12.3 引用与删除

- 素材面板会显示引用位置。引用关系除剧情节点外还包括：manifest 默认字体、运行时隐式素材（对话框、名字框、打字音）、按钮模板三态贴图、帧动画的帧、章节地图背景/装饰/热点、选项 `choice` 的 `gui` 图标等。
- 仍被引用的素材不能从项目移除（会列出前几处引用）；`button_create` / `button_update` 节点本身不算素材引用。
- 按钮模板列表会显示每个模板被剧情引用的处数（普通按钮节点、`choice` 的节点模板、选项模板都计入）；仍被引用的按钮模板不能删除。
- 移除素材只删除登记，磁盘文件保留（提示「磁盘文件会保留」）。

### 12.4 循环帧动画

在素材页点「创建帧动画」打开面板：

- **帧列表**：从「可选图片」点选加入；可拖拽重排、`↑/↓` 移动、`×` 移除、「按文件名自然排序」；每帧可单独设时长（ms），也可用「统一帧时长」（默认 100）。
- **标识**：`动画 ID`、`素材 ID`、`素材类型`（只能 sprite / background / gui）；只读显示 `描述文件`（`animations/<id>.yaml`）。
- 面板会预览帧顺序、时长、尺寸与总解码预算；创建前是本地草稿，不产生撤销记录。
- 硬性规则：帧数 ≤512；单帧时长 1–60000ms；同一动画所有帧**像素尺寸必须一致**；单边 ≤8192；唯一帧合计解码后 ≤256 MiB；动画 ID 不能与素材 ID 冲突。
- 动画可以作为背景、立绘、GUI、按钮贴图、地图素材和长文本纸张使用；存档只保存素材 ID，读档时循环动画从第一帧开始；打开菜单、翻页或失焦会暂停循环，恢复时从同一帧继续。

### 12.5 其他

- 帧动画描述文件与素材登记在保存时一起校验；手工写的动画文档也会用真实 PNG/JPEG/GIF/WebP 头检查尺寸。
- 图片/字体等二进制素材走 Git LFS；提交前注意 LFS 预检。

### 12.6 虚拟文件夹、显示名与隐藏

素材面板顶部的文件夹树是**纯编辑器**分类，只写入 `game/.vectspace/layout-v1.json`，不会移动任何文件，也不改变素材 ID、manifest 路径或运行时引用：

- **嵌套文件夹**：`＋ 新建文件夹` 建根文件夹，任意文件夹行上的 `＋` 建子文件夹，`✎` 重命名，`⇄` 把文件夹移到其它位置（含防环提示）。折叠/展开只影响显示。
- **移动素材**：拖动素材行到文件夹，或用素材详情的「移动到文件夹」下拉（键盘/菜单等价路径）。空文件夹会显示「（空文件夹）」。
- **显示名**：详情面板可编辑显示名；列表优先显示显示名，稳定 ID 与源文件路径始终单独可见。
- **隐藏**：详情面板可隐藏/取消隐藏。隐藏素材仍留在素材面板（带「已隐藏」标记，“显示已隐藏”开关控制是否列出），但**不再出现在新的选择列表**；当前已选中的隐藏素材仍然显示并标记，避免编辑时被静默清空。
- 以上编辑都是普通可撤销历史提交；撤销后分组、显示名与隐藏标记都恢复。

### 12.7 共享素材选择器

所有素材选择入口共用一个可搜索选择器，布局元数据通过 `AssetLayoutProvider` 覆盖整个编辑器（包括长文本、章节地图、按钮、动作、UI 动效与时间线等全屏工作区）：

- 节点检查器全部素材字段（背景/立绘/GUI/BGM/环境声/音效/视频/字体）、选项 `gui` 图标、幕布 `gui` 填充、长文本纸张素材与预览背景（保留 `__current__` / `__none__` 哨兵选项）、动作预览立绘、按钮三态贴图、章节地图背景与装饰/热点贴图。
- 剧情时间线的轨道/事件素材（立绘/视频轨、SFX 事件）与工作区自身的新轨道/新事件默认值；「角色」面板新建表情的立绘选择；循环帧动画的「可选图片」候选。
- 可按名称、稳定 ID、路径、文件夹搜索（不区分大小写），可按类型/文件夹过滤。文件夹筛选里「未分组」只含**没有虚拟文件夹**的素材，不含子文件夹；选定具体文件夹时才包含其子树。
- 键盘可完整操作：方向键移动、Enter 选中、Esc 关闭；有「无」/清除选项的字段会显式提供。
- 隐藏素材不会作为新选项出现，但当前值会被保留并标记「已隐藏」。**新选择/默认值永远不会静默选一个隐藏素材**：没有可见素材时使用空选择或不提供该操作，例如新建角色表情的 ＋、时间线的视频轨/ SFX 事件按钮会被禁用并提示原因（立绘轨可以继承进入时素材），而不是写入空的素材引用。

### 12.8 替换素材文件

选中静态素材后可在详情面板点「替换文件…」：

- 素材 ID 与类型被锁定；必须选一个**同格式、不同路径**的新文件（例如 `room.png` → `room_v2.png`）。扩展名或实际格式不符、目标路径与旧路径相同、素材是合成帧动画时会就地报错。
- 每次替换都以**当前登记路径**为准（包括尚未保存的暂存路径），但原始文件路径与所有先前暂存的替换路径都**永远保留为禁止目标**：宿主机不会覆盖原文件，选择器也遵循同一规则，并在重名时自动给出唯一的 `_v2` / `_v3` 建议名、在应用前就地报冲突。被取代的暂存 token 与暂存二进制保留以便重做，保存只提交与 manifest 路径一致的那个。
- 新文件先经宿主机检查并暂存，再就地更新同一素材行；成功后该行显示「待保存」，保存时才写入 manifest/layout。
- 新路径与哈希会立即反映到预览 URL，撤销或取消时旧文件与旧 token 都不受影响；旧二进制作为未登记的回滚副本保留在 `assets/` 中，可以用它手动恢复。
- 合成帧动画不能直接替换，请改换它的帧图片；帧图片替换会校验动画尺寸约束。

## 13. 项目设置、变量、角色与立绘动作库

项目数据分布在活动栏的几个独立面板里：「项目设置」（活动栏底部）、「角色」、「变量」和「资源库」。每个面板只显示自己的内容。

### 13.1 项目设置

| 字段         | 说明                                |
| ------------ | ----------------------------------- |
| 内容版本     | `content_version`；内容大改后应更新 |
| 默认语言     | `default_locale`（如 `zh-CN`）      |
| 项目入口场景 | 游戏启动进入的场景                  |

如果保存时内容文档变了但 `content_version` 没变，会提示「剧情、动效或流程内容已经改变，但 content_version 没有更新。继续保存会保留旧的已读、历史和完成状态。仍要保存吗？」

### 13.2 剧情变量

活动栏「变量」面板。每个变量包含：

| 字段   | 取值                                 |
| ------ | ------------------------------------ |
| 作用域 | `save · 随存档` / `profile · 跨存档` |
| 类型   | boolean / integer / number / string  |
| 默认值 | 必须符合所选类型                     |

- save 变量写入存档快照，读档会回滚；profile 变量存在 `profile.json`，读档不会回滚，适合累计进度。
- 变量仍被剧情引用时不能删除（`变量 X 仍被 N 处剧情引用，不能删除。`）。
- 变量可以在对话里用 `[var=id]` 插值，也可以被 `set`、`condition`、选项条件、按钮点击行为使用。
- `window.main.title` 与 `window.secondary.title` 是内置的只读文本变量（见 7.4「窗口与场景用途」）：
  变量面板里不会出现它们，也不能声明同名变量；它们只出现在可读取的位置（文本插值、条件、操作数）。

### 13.3 角色与表情

活动栏「角色」面板。角色字段：

| 字段            | 说明                         |
| --------------- | ---------------------------- |
| 显示名          | ≤64 字符                     |
| 姓名色 / 正文色 | 取色器或 `#RRGGBB`（可留空） |
| 默认表情        | 未指定表情时使用             |
| 默认缩放        | 立绘整体缩放                 |

每个表情：

| 字段       | 说明             |
| ---------- | ---------------- |
| 素材       | 仅 sprite 类型   |
| 锚点 X / Y | 0–1              |
| 偏移 X / Y | 局部修正         |
| 表情倍率   | 该表情的缩放修正 |

角色被 `say` 引用时不能删除。表情切换不会改变立绘实例的变换，也不会影响对话布局。

### 13.4 立绘动作库

动作是可参数化、可复用的相对通道动画：

| 字段        | 说明                                                                                               |
| ----------- | -------------------------------------------------------------------------------------------------- |
| 动作名称    | 显示用                                                                                             |
| 默认时长 ms | 调用方可覆盖                                                                                       |
| 结束姿态    | 保持最后一帧 / 恢复动作前姿态                                                                      |
| 参数        | 每个参数有默认值、最小值、最大值                                                                   |
| 变换通道    | X 偏移、Y 偏移、旋转偏移、整体/横向/纵向缩放倍率、透明度倍率                                       |
| 关键帧      | 时间、数值、缓动（linear / ease in / ease out / ease in-out / step）、参数（固定值或引用某个参数） |

- 通道相对目标当前姿态：位置和旋转是偏移，缩放和透明度是倍率；参数范围在校验时检查。
- 动作库在活动栏「资源库」面板的「立绘动作」分组里，每个动作占一行。面板里**只做列表管理**；点行上的铅笔按钮进入独占的关键帧工作区，动作的全部字段（名称、时长、结束姿态、参数、关键帧）都在工作区里编辑。
- 关键帧工作区与其他工作区共用同一套关键帧界面（`TimelineSurface`）：同一把时间尺、
  走带、吸附、框选、拖动、复制粘贴、缓动曲线与撤销分组。
- 工作区左侧是动作属性（名称、默认时长、结束姿态）、预览基准姿态和参数表。动作存的是
  相对值，所以关键帧按「预览基准姿态」换算成绝对坐标显示；基准姿态只影响编辑器预览，
  不写入动作文件。
- 绑定参数的关键帧在时间线上显示为该参数的默认值。只拖动时间会保留绑定；直接改数值
  即解除该帧的参数绑定，避免悄悄丢掉作者的选择。
- 行上的「⋯」菜单提供创建副本、重命名、移除；被 `action` 节点引用时不能移除，重命名会更新引用。
- 在剧情里用 `action` 节点调用；需要把动作「烤」进某条时间线时，用检查器「⋯」菜单的「展开为关键帧时间线」（可逆，普通调用仍保持可复用）。
- 动作对所有 Sprite 通用（节点类型在菜单里叫「Sprite 动作」）：物品、屏幕 UI 图像和固定文本块都可以复用同一个动作。

### 13.5 场景固定文本与粒子效果库

固定文本块属于场景内容：在对应场景下的「固定文本块」分组新建和编辑。
已有文本按 Sprite 节点和时间线引用自动归组；新建但尚未引用的文本，归属记录在
`.vectspace/layout-v1.json` 中，保存并重新打开后仍保留。跨场景复用及未归属文本有独立兼容分组，
不会因为删除场景而自动删除文本资源；同一个资源仍只编辑一份。
粒子效果是可复用定义，继续在「资源库」面板中管理。

两类内容的管理方式与立绘动作一致：

- 分组标题右侧 ＋ 新建（文件分别写到 `text_blocks/<id>.yaml` 与 `particles/<id>.yaml`）；
  行上「⋯」菜单提供重命名（同时改写所有引用）、创建副本、从项目移除；
- 仍被引用时不能移除，错误提示会列出引用位置（Sprite 节点、时间线 Sprite 轨道或粒子节点）；
- 所有编辑都进入撤销/重做，并与剧情、素材一起在同一次原子保存中写盘；
- ID 与素材、帧动画、立绘动作、另一类视觉文档共用一个命名空间，不能重名；
- 点击行进入专用工作区：左侧是字段，右侧是共享 `SceneSurface` 的实时预览（与游戏同一套渲染）。

**固定文本块工作区**

| 字段          | 说明                                                                         |
| ------------- | ---------------------------------------------------------------------------- |
| 富文本内容    | 沿用对话标记与 `$…$` / `$$…$$` 公式；不支持 HTML/CSS，停顿/变速等控制标记不生效 |
| 宽度 / 高度   | 固定框，1–4096 且总像素 ≤ 4,194,304；超出部分被裁剪                          |
| 字号 / 行高   | 1–512 / 0.5–8                                                                |
| 内边距        | 小于宽高较小者的一半                                                         |
| 字体          | 留空使用项目默认字体；只能选择 font 素材                                     |
| 水平/垂直对齐 | 左/中/右，顶/中/底                                                           |
| 文字颜色/背景 | `#RRGGBB(AA)`；背景可关闭（透明）                                            |

文本块整体栅格化成一张纹理，多个 Sprite 共用；移动、缩放、旋转、淡入淡出都不会重新排版，
只有内容、排版或字体文件变化时才重新生成。它不会逐字显示、分页或等待点击。

**粒子效果工作区**

| 字段                  | 说明                                                       |
| --------------------- | ---------------------------------------------------------- |
| 粒子图片              | 单张静态图片（background / sprite / gui），最大 512×512     |
| 混合模式              | 普通 / 叠加发光                                            |
| 发射范围              | 单点或矩形区域（宽、高）                                   |
| 每秒数量 / 爆发数量   | 持续发射率（0–10000）/ `burst` 一次发射的数量              |
| 同时存在上限          | 1–5000；整个画面最多 10000                                 |
| 寿命、速度、缩放等    | 最小–最大范围，每个粒子由随机种子确定性抽样                |
| 加速度 / 透明度变化   | 整体加速度；从初始透明度线性变到结束透明度                 |
| 随机种子              | 相同种子 + 相同时刻总是同一画面                            |

预览可切换「持续发射 / 单次爆发」；爆发模式按 `burst_count` 播放，发射率为 0 也能预览。
按空格或重播按钮，从 0 重新触发一次爆发；在文本输入框、输入法组合输入或弹窗中不会抢占空格。
播放、暂停、停止及播放头定位都只操作预览，不产生撤销记录；定位时直接计算粒子状态，同一时刻和种子得到同一帧。

舞台上的点标记/矩形表示实际生成范围，可拖尺寸手柄调整矩形宽高。拖动期间实时更新轮廓和宽高标签，
松手后重建粒子并只产生一次撤销记录；Escape 或取消拖动不写入修改。
定义工作区中移动中心只改变预览位置（不保存），因为定义本身没有绝对舞台位置。
要修改剧情中的生成点，请打开 `start` 或 `burst` 粒子节点并拖动其生成点标记，位置保存到节点的 X/Y。
单个粒子始终不可选择。

## 14. 校验与问题排查

编辑器有**两层校验**：

1. **实时校验**：每次编辑立即运行，结果显示在活动栏「问题」面板、状态栏和节点卡片右上角的问题数上。
2. **完整校验**：保存、点工作区顶栏的「校验」或项目菜单「完整校验项目」时运行，与游戏启动时的校验完全一致。

「问题」面板说明：

- 按场景分组（章节地图的问题归入「章节地图」，项目级问题归入「项目」），组标题显示条数；组内错误在前、警告其次。
- 每条显示严重级图标、消息和节点 ID；悬停可看错误码。
- 点击任意一条会跳到对应场景、节点或地图对象。
- 空态显示「当前项目没有发现问题」。
- 保存时有错误会打开问题面板并提示「存在 N 个错误，修复后才能保存。」警告不会阻止保存，但会在保存提示里汇总。

常见错误类型：

| 类别         | 例子                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------- |
| 引用缺失     | 目标节点不存在、变量未声明、素材未登记、模板缺失                                         |
| 类型不匹配   | 条件比较两侧类型不兼容、`mod` 除数为 0、插值变量不是数值                                 |
| 范围越界     | 时长/音量/字号/坐标超范围、关键帧越界                                                    |
| 结构错误     | 文稿缺少开始节点、重复热点、接续文稿重复定义样式、视频轨超过一条                         |
| 路径/命名    | ID 非法或重复、路径冲突、`..` 越界、路径覆盖受管制文件                                   |
| 窗口与计时器 | 场景用途不符（副窗口专用场景被跳转/入口/地图引用）、写入只读窗口标题变量、计时器目标无效 |
| 窗口布局     | 窗口位置/大小越界或都没设置、层级操作无效、等待完成的位置/大小被计时器引用               |

## 15. 保存、撤销与数据安全

### 15.1 保存流程

1. 先提交当前未完成的编辑草稿（无效输入会阻止保存并提示修正）。
2. 本地校验；有 error 直接拦截。
3. 对完整候选项目运行完整校验。
4. 通过后事务化写入：多文件保存先写 `.vectspace/tmp/<save-id>/`，旧文件按相对路径备份到 `.vectspace/backups/<save-id>/`，最多保留最近 10 代。
5. 只有**字节实际变化**的文档会被序列化替换；未修改的文档保持原字节（注释和手工格式不会被规范化）。

保存成功提示形如：`项目已安全保存（N 个文件，删除 M 个）。备份位于 .vectspace/backups。`

### 15.2 外部改动保护

打开项目时会记录内容的 SHA-256 指纹。如果保存前发现文件被编辑器之外的手工编辑改动过，保存会停下，避免无声覆盖别人的修改。

### 15.3 撤销/重做

- `Ctrl+Z` 撤销，`Ctrl+Y` 或 `Ctrl+Shift+Z` 重做；顶栏按钮等价。焦点在文本框里时，这些键撤销 / 重做的是文字本身。
- 可撤销的删除（节点、场景、资源库条目等）会弹出带「撤销」按钮的通知；项目在此之后又有改动时，通知里的「撤销」不会误撤后来的修改。
- 拖拽类手势（画布移动、地图拖动、长文本排版）在松手时合并为**一条**撤销记录。
- 未提交的输入框草稿在切换节点前会被提交或要求修正。

### 15.4 编辑器专属数据（不进剧情 YAML）

| 数据                            | 位置                                                      |
| ------------------------------- | --------------------------------------------------------- |
| 节点坐标、画布视口              | `game/.vectspace/layout-v1.json` → `scenes`               |
| 时间线/长文本预览路径与变量覆盖 | 同文件 → `timeline_previews`                              |
| 保存事务的临时与备份            | `.vectspace/tmp/`、`.vectspace/backups/`（均被 Git 忽略） |

### 15.5 删除的安全网

- 删除场景、素材、动作、按钮模板、UI 动效都只移除项目登记，磁盘文件保留。
- 节点删除会把指向它的引用重定向到保留节点，并清理布局与预览设置。
- 有未保存改动时关闭窗口或切换项目会弹确认。

## 17. 常见任务配方

### 17.1 加一段带公式的对话

1. 剧情图选中一个 `say` 节点（或在脚本视图按 `Enter` 插入新句）。
2. 检查器「说话人模式」选「已定义角色」，选角色。
3. 正文写：`设 $V$ 是一个向量空间，当前得分 [var=score]。` 需要停顿就写 `[pause=500ms]`。
4. 检查器下方「实际渲染预览」确认公式和插值显示正常；`Ctrl+S`。

### 17.2 加一个分支选项

1. 工作区下拉选「逻辑 · 选择」，点「＋ 添加节点」。
2. 检查器点「＋ 添加选项」，填写文本与目标节点；需要时打开「显示条件」「可用条件」。
3. 若选项要加分，先添加 `set` 节点（例如 `score` 加 1），把选项目标指过去。
4. 想用按钮皮肤与自由摆位，就在「模板表现」勾选 `启用 presentation`：锚点会自动等于旧版面板中心，不会跳动；再选默认按钮模板、方向与间距，需要时为单个选项选模板与 `gui` 图标。
5. 检查器底部「真实预览」用 Rust 运行时渲染实际选项（含禁用项与 KaTeX 标签）；确认布局后再保存。

### 17.3 做一段黑板讲解

1. 添加 `long_text` 节点，双击进入全屏工作区。
2. 右侧「推进段落」逐段写文本，需要换纸的段落勾「从新纸张开始」。
3. 在舞台上拖动文本块、调整文本区域；用顶栏「播放预览 → 补全 → 下一分段」检查节奏。
4. 内容太长时用「从此处分成接续文稿」，在两段之间插入别的节点。
5. 保存；运行时玩家点击推进，读档会恢复已写出的段落。

### 17.4 做一段镜头运动

1. 添加 `timeline` 节点，设置时长，双击进入时间线工作区。
2. 底部选「镜头轨」→ `＋轨道`；用「镜头」工具在舞台上摆好机位并缩放/旋转。
3. 在通道上双击添加关键帧，设置缓动；用顶栏播放预览。
4. 需要时加 `＋SFX` / `＋闪光` 事件；保存。

### 17.5 做一个可点的按钮

1. 活动栏「资源库」→「按钮模板」分组的 `＋` 新建，点铅笔按钮进工作区设置三态贴图、尺寸和状态动画。
2. 剧情中添加 `button_create` 节点：填实例 ID、选择模板、设置位置/大小/层级。
3. 配置「点击行为」：修改变量、推进剧情、跳转到指定节点，或打开存档/设置/历史记录面板。
4. 需要移动或换样式用 `button_update`；不再需要时用 `button_remove`。

### 17.6 给对话框加位移动效

1. 活动栏「资源库」→「UI 动效」分组的 `＋` 新建，点铅笔按钮进工作区。
2. 「添加目标」选「对话框整体」，加 `offset_y`、`opacity` 等通道，双击通道加关键帧。
3. 回到「资源库」面板，把 `对话框出现` / `对话框收起` 的默认绑定设为该动效；或只在某个 `dialogue_ui` 节点的「本次动效」里使用。
4. 也可以添加 `ui_motion_play` 节点在剧情中主动播放。

### 17.7 做一段循环动画背景

1. 「素材」页点「创建帧动画」。
2. 选入帧、设置每帧时长（或用统一帧时长），确认尺寸一致。
3. 填 `动画 ID`、`素材 ID`、选类型（background / sprite / gui），点创建。
4. 在 `background` 节点选择这个素材；`Ctrl+S` 保存后才写入 manifest。

### 17.8 复用立绘动作

1. 活动栏「资源库」→「立绘动作」分组的 `＋` 创建动作，点铅笔按钮进入关键帧工作区，设置通道关键帧、参数与结束姿态。
2. 剧情里先有 `sprite` 显示立绘，再加 `action` 节点选择目标立绘实例与动作；需要覆盖时长或参数就在节点里改。
3. 想把它固定成一次性时间线，用检查器「⋯」菜单的「展开为关键帧时间线」。

### 17.9 加一个章节地图热点

1. 顶栏「章节地图」进入工作区（首次会自动创建）。
2. 工作区左栏「未放置的场景」点 `＋ 场景id`，或拖 Scene 到画布。
3. 检查器设置标题、素材、X/Y/宽/高，必要时设置显示条件与 hover 文案。
4. 点「校验」确认无误，再「保存」。

### 17.10 批量插入一批对话

1. 在外部把台词整理成「角色⇥正文」每行一条（Tab 分隔）。
2. 脚本视图选中要插入位置的节点，`Ctrl+V` 粘贴。
3. 在「批量粘贴预览」里核对，确认后按顺序插入；用 `Ctrl/⌘+点击` 多选、批量改角色。

### 17.11 配方：双窗口联动与等待动画

仓库自带一组演示场景：`window_pair_main`（主窗口）与 `window_pair_side`（副窗口专用）。它们展示：

1. 两个窗口互相改标题，并在对白里用 `[var=window.secondary.title]` 引用对方当前标题。
2. 副窗口先 `block` 主窗口，选择「开门」后依次 `window_title` → `unblock` → `advance`，让主窗口恰好翻一页；
   主窗口随后反过来 `block` 副窗口，收尾动画播完再 `unblock` + `advance` 推进副窗口。
3. 副窗口的「开门」选项依赖变量 `pair_ready`。主窗口用一个单次计时器在 3 秒后把它置为 true，
   选项会在玩家没有任何操作时自己亮起来（选项条件随变量实时刷新）。
4. 主窗口在等待期间用重复计时器每 1.5 秒播放一次 `sprite.bounce`（目标是一个未开启「等待完成」的 `action` 节点），
   离开等待处后用 `stop` 节点显式停止。
5. 副窗口打开后，主窗口先用 `window_geometry` 把自己放到工作区左侧（逻辑大小 960×540，600 ms，等待完成），
   再把副窗口贴到主窗口右侧；摆放方法见 17.12。
6. 副窗口里选「开门」后，先对主窗口 `window_layer` 提到最前，再解除阻挡并推进；收尾时主窗口先置顶、说完话再恢复普通层级。

演示从章节地图热点 `window_pair` 进入，依赖 manifest 里声明的 save 作用域 boolean 变量 `pair_ready`（默认 false）。
这是在编辑器里可以直接打开、改写和单场景预览的普通内容。

### 17.12 配方：摆放窗口、置顶与抖动

目标：打开副窗口后，让两个窗口并排出现在屏幕上，再用层级和计时器做一点动静。演示场景 `window_pair_main` / `window_pair_side`
已经按这个思路做了前几步。

1. **主窗口放到左边**：在「打开副窗口」之后加一个「窗口位置/大小」，目标选主窗口；位置的参考对象为屏幕工作区、
   参考点 X 0.27 / Y 0.5、窗口锚点 0.5 / 0.5（用窗口中心对准工作区左侧约四分之一处）；大小选逻辑像素 960×540；
   时长 600 ms、缓动「缓入缓出」，**勾选「等待完成」**。
2. **副窗口贴到主窗口右侧**：紧接着再加一个「窗口位置/大小」，目标选副窗口，位置预设选「贴在另一窗口右侧」
   （参考对象为另一个游戏窗口，参考点 (1, 0.5)，锚点 (0, 0.5)，偏移 X 16）。因为上一个节点勾选了等待完成，
   副窗口贴的是主窗口**到位之后**的位置。
3. **选完后把主窗口提到前面**：副窗口里玩家选「开门」之后，加「窗口层级」，目标主窗口、操作「提到最前」。
   它不抢焦点，玩家的键盘焦点仍留在副窗口。
4. **收尾演示置顶**：结束前对主窗口做「置顶」，对白说明之后再做「恢复普通层级」。置顶会一直保持到恢复，两个节点要成对出现。
5. **抖动或漂移**：新建两个方向相反的「窗口位置/大小」节点（预设「相对当前位置偏移」，一个偏移 X +6、一个 −6，时长 60–100 ms，
   **不要**勾选「等待完成」），不接入主线；再用两个重复计时器分别触发它们，间隔相同、首次延迟相差半个间隔
   （例如都每 200 ms，首次延迟 0 与 100 ms），窗口就会左右抖动。离开等待处后用「停止」节点停掉两个计时器。
   只用一个偏移节点则是持续漂移。
6. 在编辑器里预览这些场景时，预览只会提示「预览不会移动或缩放真实窗口」，不会真的移动编辑器；
   要看实际效果请在桌面运行游戏（可以从章节地图重演 `window_pair` 热点）。

### 17.13 配方：公式卡片、物品与下雪

演示场景 `visual_showcase`（章节地图同名热点）就是这条配方的完整版本。

1. **公式卡片**：对应场景下的「固定文本块」＋ 新建，内容写 `$$e^{i\pi}+1=0$$`，设好宽高、对齐和半透明背景色，
   右侧预览确认没有被裁剪。
2. **放到画面上**：加一个 Sprite 节点，来源选「固定文本块」，类别选「固定文本」；需要不随镜头移动时把坐标空间改成「屏幕」。
3. **物品与 UI 图标**：再加 Sprite 节点，来源选「统一图片来源」，类别分别选「物品」「独立 UI」；物品可以打开布局框
   （例如 220×220、完整包含）统一尺寸。
4. **共享动作**：对物品和文本块各放一个「Sprite 动作」节点，选同一个 `sprite.bounce`。
5. **下雪**：资源库「粒子效果」＋ 新建，选一张 ≤512×512 的小图，发射范围选矩形、宽度略大于画面；
   用预览的播放头确认第几秒的效果。剧情里加「图片粒子」节点，动作「持续发射」，Y 放在画面上方。
6. **整体运动与收尾**：在时间线工作区里选中对象列表的 `EMT` 发射器拖动，会生成「发射器整体轨」；
   需要一次性的火花时用「单次爆发」；结束前用「停止并清除」，或用「清除画面」一起淡出。

### 18.3 FAQ

**Q：启动即报素材缺失或 LFS 指针？**
执行 `git lfs pull`，或在安装 Git LFS 后重新 clone；启动前预检会列出受影响路径。

**Q：提示 Cargo 不在 PATH？**
`$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"`，或在新的终端里用 `npm run editor:dev`。

**Q：为什么我改了节点位置，YAML 里没有坐标？**
坐标属于编辑器布局，存在 `.vectspace/layout-v1.json`，这是有意的（避免剧情文件被布局噪音污染）。

**Q：为什么保存被拒绝？**
底部/问题页会给出错误码和位置。点击问题直接跳过去修复；有 error 时编辑器不会写入任何文件。

**Q：为什么删除场景/素材后文件还在？**
删除只移除登记，文件保留作为恢复副本。要真正删文件请手动处理（注意 LFS 与引用关系）。

**Q：时间线里为什么找不到字幕轨？**
时间线有立绘 / 镜头 / 视频 / BGM / 四槽环境声 / 按钮轨道；对话和字幕由 `say` 与对话框负责。

**Q：预览结果和游戏里不一致怎么办？**
先确认左侧「问题」页没有 error，再确认预览路径选择（时间线/长文本检查器里的「请选择预览路径」）覆盖了正确的分支；预览使用与游戏相同的 Rust 运行时和共享文本实现。

**Q：内容大改后旧存档会怎样？**
读档按存档里的快照和当前节点 ID 恢复；如果 `content_version` 未更新而内容已变，保存时编辑器会提醒，旧的已读/历史/完成状态可能保留而非重置。
